## Answer to the user

**How we get backward compatibility, better performance, and speed — on evidence, not slogans.**

**Compatibility: clone Electron's observable contract, not its implementation.** Every Electron behavior the corpus depends on (API shape, event order, destroyed-object errors, lifecycle sequencing, error text) is reproduced once, at three seams, over Keld's existing primitives: `@keld/electron` (TypeScript facade, pure consumer of `@keld/api`) owns EventEmitter semantics, tombstones and ordering; `keld-compat` (Rust, behind `keld-guard`) owns only what mints authority or needs a native handle (webview identity, host-minted `event.sender`, window parenting/modals, scheme declaration); a renderer compat script runs in the KEL-142 isolated content world. Nothing Electron-shaped enters `keld-core`/`keld-ipc` [fact: 04 §3, kel142 §4.3]. Each surface lands a conformance entry citing the pinned v44.4.5 doc sentence *before* code; divergences are visible ▲ with a test or ✘ fail cells — never prose [fact: compat-scoreboard KEL-72 rows].

**The hard, measured problem is blocking.** draw.io's close dance calls `dialog.showMessageBoxSync`; Electron blocks the main process. Keld's Bun kipc client is an event-loop client; parking the Bun main thread stops draining the socket after exactly 8,192 bytes of host→Bun traffic [fact: park-probe re-run today; `sysctl net.local.stream.sendspace=8192`], and 02 §7's 5 s writer timeout would then surface as `KELD-IPC-006` [inference: probe server was Bun, not the Rust host]. Consensus: no second kipc link per role (that mints a second principal, KEL-75), no fake-async sync APIs (KEL-127), no host auto-close on timeout. The only candidate is a worker-owned single-link transport, which is a KEL-80 wire-protocol/public-API change, gated by a 1–2 day spike before any sync emulation lands. Host-side close/quit vetoes need no blocking at all: Electron itself returns NO from `windowShouldClose:` and AppKit's `applicationShouldTerminate:` can reply later [fact: Electron delegate source; Apple docs].

**Performance: measured, not promised.** Today we can say: Windows host-process RSS 19,552 KB vs Electron 89,140 KB (Electron won total process tree); host-only first paint 469 ms vs Electron 275 ms (Electron leads); a 1-session, publication-ineligible kipc p99 ≈101 µs [fact: budget-scoreboard]. Targets (01 §5) and projections are separate classes. Compatibility must not cost speed: a facade-overhead delta (`@keld/electron` minus raw `@keld/api`) and a renderer-inclusive invoke RTT get registered metric ids before any IPC sentence about migrated apps.

**Faster: one proof, narrow denominator, honest profile.** The first proof is drawio-desktop on macOS under an explicitly declared `legacy` profile (`LegacySandboxOff` in every KEL-74 record; "brokers correct, containment forfeited"), scoring install + activation + a 4-step primary workflow only. Spine order (#312) is unchanged; compat lanes consume KEL-142 artifacts on disjoint crates. Zettlr waits on a WKWebView sync-XHR experiment (6 `sendSync` sites; draw.io has 0).

**Contested (labeled):** (1) preload in the KEL-142 isolated world vs a third world — decided by a leak test, not prose; (2) whether Electron's main-process JS re-enters during a Cocoa modal — [unknown], fixture required; (3) which risk is the program killer — the measured link-stall gates the first proof; the legacy-only headline is the program-level honesty risk.

- **Close and quit vetoes are async AppKit hooks; deadline expiry keeps the window open** [resolved, grilling] — The host never blocks its UI thread on Bun: windowShouldClose: returns NO and the host closes programmatically after Bun allows; app quit routes through applicationShouldTerminate: (delay, then reply(toApplicationShouldTerminate:)) because windowShouldClose is not called on quit.
