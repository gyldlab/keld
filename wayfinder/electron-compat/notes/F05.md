# F05 — session-network-protocol

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

F05 covers 43 entities / 368 members (Session 88, protocol 18, net/ClientRequest/IncomingMessage/WebSocket 51, DownloadItem 28, WebRequest 8, Cookies 5, ServiceWorkers/ServiceWorkerMain 15, Extensions 7, netLog 3, 29 structures). Corpus demand is narrow and concrete: Zettlr's `protocol.handle('safe-file')` (unprivileged scheme, serves any readable absolute path, consumed by 23 renderer/main files), Zettlr's `ses.clearStorageData({storages:[cookies,localstorage,shadercache]})` in 12 window factories, draw.io's `session.defaultSession.webRequest.onHeadersReceived` (CSP for all contents) + `onBeforeRequest({urls:['file://*']})` (block file loads outside the app dir), draw.io's indirect `net.request` via electron-updater (`session.fromPartition('electron-updater',{cache:false})`), Zettlr's `net.online` gate; neither app installs a permission handler (so Electron's documented default-allow applies to them today); Extensions appear only in Zettlr's non-packaged dev path; quick-start uses nothing in F05. Keld today: no scheme registration (keld-wv `WebEngine` v0 omits `register_scheme`; no WKURLSchemeHandler/WebResourceRequested/register_uri_scheme code), no session/cookie/download/net facade (`@keld/electron` = app only; keld-native = fs.read/fs.write), keld-guard already evaluates `app.net.connect` URL scopes with the live authority rule but "no URL-valued capability is wired to it yet", `web.camera`/`web.microphone` default-deny with `Principal::Webview` is live, KEL-135 gives one host-owned persistent profile per signed app (+ ephemeral dev) with no partition concept, KEL-79 (origin/resource transport) is parked by owner orders and has no spec file. Six decision atoms: (1) scheme declaration is static host config, `protocol.handle` is a Bun producer behind the arch-05 host resource adapter; (2) missing permission handler = guard default-deny, present handler only narrows after guard Allow; (3) main-process `net` is Bun networking under `app.net.connect`, never engine session — where egress is enforced for strict roles is an open research/prototype question; (4) `webRequest` is not generically emulable on system engines — migrate the two corpus uses to static `web.csp` + resource scopes, API itself ▲; (5) one default session = KEL-135 profile; storage/cookie ops become host-brokered profile operations, partitions ▲ until KEL-135 grows; (6) a documented-never set (Extensions, netLog, TLS-trust overrides in strict, HID/USB/Serial/Bluetooth/WebAuthn choosers, ServiceWorkerMain, sharedDictionary, networkEmulation). Insufficient evidence is stated as unknown rather than filled in.

## Reuse points

- keld-guard `evaluate` with the live URL-scope authority rule (KEL-208) for `app.net.connect` — do not add a second URL matcher for net/proxy/scheme origins.
- `Principal::Webview { id, generation }` + `MediaPrincipalRequired`/KELD-GUARD006/007 pattern in crates/keld-wv/src/media.rs — the template for every session permission string (request+check unified).
- KEL-102 webview policy-injection public API and guard-before-handler boundary (docs/specs/kel102-host-guard-enforcement.md §4) — session permission handlers hang off it, not off a compat-owned callback table.
- KEL-135 `ProfileIdentity` / `WebProfileSelection` / platform store table — `session.defaultSession`, `isPersistent`, storage clears and cookies are operations on this profile; partitions are a KEL-135 extension, not a compat store.
- Architecture 05 §2 host resource adapter flow (binding to active WebView + navigation generation, guard before bytes) and architecture 02 §3 `keld://c/{channel}` bulk lane — the only place `protocol.handle` producers may plug in.
- keld-native `FsBroker` scope semantics (first-match ScopePermit, 8 MiB ceiling, component walker) — a scheme handler's file reads reuse these grants; no scheme-specific file authority.
- KEL-89 keld-auth host-broker chain tables (per-OS custom-scheme registration via `deeplink`, loopback listener ownership) — `app.setAsDefaultProtocolClient`-style OS registration and any auth-related scheme must not be re-implemented by F05.
- KEL-53 keld-update adapter (`autoUpdater` facade) — removes draw.io's only main-process `net.request` demand; F05 must not emulate electron-updater's download path.
- Architecture 03 manifest shapes: `app.net.connect`, `app.system[]`, `windows.<w>.web.csp` and `channels` — storage/cookie ops and CSP mapping use these vocabularies, not new top-level keys.
- `keld.compat.ts` quirks flags + scoreboard ▲/✘ (arch 04 §3 layer 5) and `keld_compat::evidence` + lifecycle corpus denominator (KEL-74/KEL-237) — every F05 cell lands as a conformance entry citing the v44.4.5 doc receipt before implementation.
- `@keld/api` `channels.handle(descriptor, handler)` descriptor pattern and KEL-98/KEL-136 echo codegen — the `protocol.handle` and `web-data` channel contracts are generated from one source, no new IDL.
- KEL-75 role declaration / window-bound lifecycle — a `protocol.handle` producer is the primary role or a declared window-bound role, never a new process kind.
- Research 214 rules — selected Electron spec identities (api-session-spec, api-net-*-spec, api-net-custom-protocols-spec) may be cited only under a future per-surface spec with immutable blobs; local HTTP fixtures need a manifest fixture service, never general net.

### F05-D1 — How are Electron custom schemes (`protocol.registerSchemesAsPrivileged` + `protocol.handle`) realized when the scheme must exist before any engine view is created and the handler runs in a supervised Bun role?

**Proposed answer:** Scheme declaration is static, host-owned configuration (`keld.config.ts` scheme table with explicit privilege bits: standard/secure/supportFetchAPI/corsEnabled/allowServiceWorkers/stream/bypassCSP), consumed by keld-wv at engine construction on all three platforms; `keld migrate` lifts the app's `registerSchemesAsPrivileged` array into that table. `protocol.handle(scheme, handler)` is a facade that registers the Bun role as the producer for that scheme behind the architecture-05 host resource adapter: engine request → adapter binds active WebView+navigation generation → keld-guard evaluates the scheme/origin/method against the declared scheme and the producer role → routed kipc request to the Bun handler (Electron `Request`-shaped: url, method, headers, body, initiatorOrigin) → bounded `Response` chunks back through the adapter (WKURLSchemeHandler / WebResourceRequested / WebKitURISchemeRequest).
