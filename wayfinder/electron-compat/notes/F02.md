# F02 — windowing

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

F02 covers 32 entities / 606 raw members (BaseWindow 187, BrowserWindow 204 incl. the 126 inherited methods, View/WebContentsView/BrowserView/ImageView, 11 TouchBar classes, 2 option structs with 52+2 fields, WebPreferences 46 fields, JumpList/Task/Thumbar structs). [fact] Keld today has NO BrowserWindow facade: the host owns exactly one primary window per app session (keld-wv v0 WebviewSpec = title+size+initial; one window-filling webview per window), keld-core LifecycleSession only counts windows and emits Ready/LastWindowClosed, close is uncancelable (tao CloseRequested -> LastWindowClosed), no window id crosses kipc, no chrome options (titleBarStyle/vibrancy/frame/transparent) exist in any backend, and the destination keld-core window registry is TARGET per product-status/arch 01. Corpus demand ranks: (1) constructor + show:false/ready-to-show + backgroundColor (Zettlr 14 sites, drawio, progress-bar), (2) cancelable 'close' with async veto then explicit destroy()/close() (drawio + Zettlr both), 'closed' bookkeeping, isDestroyed, (3) getAllWindows/getFocusedWindow/fromWebContents, (4) maximize/minimize/fullscreen state + their events, (5) mac hiddenInset+vibrancy, win/linux frame:false+titleBarStyle hidden+titleBarOverlay (Zettlr), (6) parent/modal (Zettlr modals, drawio hidden export child), (7) setWindowOpenHandler with overrideBrowserWindowOptions (drawio). Six decision atoms: host-owned window identity mirrored in the facade; a two-phase host<->Bun close protocol (close veto, destroy, destroyed-object fence); ready-to-show from a hidden-window paint oracle (prototype-gated, highest risk); WebPreferences triage (policy vs engine-toggle vs never); BrowserWindow implemented once as BaseWindow+one WebContentsView with multi-view/BrowserView deferred to Tier 3; window chrome option tiering per engine. Key invariant consequences: missing setWindowOpenHandler must stay deny (Keld) and be an explicit divergence from Electron; nodeIntegration/contextIsolation:false/sandbox:false/webSecurity:false/offscreen/getNativeWindowHandle/hookWindowMessage are never or legacy-profile only; JumpList `program` must be pinned to the app's own executable.

## Keld state

[fact] No BrowserWindow/BaseWindow/View facade exists: packages/@keld/electron/src exports only `app` (whenReady/isReady/quit/on/off/removeListener) over @keld/api app lifecycle (whenReady/isReady/onLastWindowClosed/quit). [fact] Host window ownership is live for exactly one primary window per app session: keld-wv v0 `WebEngine::create(&WebviewSpec{title,size,initial})` (crates/keld-wv/src/engine.rs; doc comment 'v0 is one window-filling webview per window', no HostHooks/Anchor/post/register_scheme), backends wkwebview (wry/tao interim), webview2 (direct COM), webkitgtk (wry/GTK3). [fact] Close is uncancelable: tao `WindowEvent::CloseRequested` -> `AppWindowEvent::LastWindowClosed` in all three backends (wkwebview/mod.rs:387-401, webkitgtk/mod.rs:469-474, webview2/mod.rs:2594-2605); keld-core app_session `coordinate_window_events` maps NavigationReady->signal_ready and LastWindowClosed->signal_last_window_closed; `AppWindowCommand::{Quit,Fatal}` are the only host->UI commands. [fact] `keld_core::LifecycleSession` has `window_opened()/window_closed()` counters emitting `LifecycleEvent::LastWindowClosed` at zero (lifecycle.rs:132-150) over LIFECYCLE_CHANNEL (ChannelId 3); kipc channels live: ECHO(1), FS(2), LIFECYCLE(3). [fact] No window id, bounds, visibility, focus or chrome state crosses kipc; no titlebar/vibrancy/frame/transparent code in any backend (grep empty). [fact] keld-core/src/lib.rs claims 'Owns ... the window/webview registries' but product-status.tsv crate.keld-core/crate.keld-host say the destination registry is absent; research 214 row 'BrowserWindow core: SUBSTRATE-BLOCKED, H7 window registry remains TARGET'. [fact] keld-guard `Principal::{AppProcess, Webview{id,generation}}`; v0 `evaluate` denies any non-AppProcess principal (KELD-GUARD006); arch 03 §2 shows a destination `"windows": {"main": {"channels":[...], "web":{"csp":...}}}` manifest block that the parser currently ignores like `$schema`; KEL-102 D-notes: 'Until window grants ship ... window-level grants' not live. [fact] WebView2 backend registers deny-all `add_NewWindowRequested` before first navigation (keld-wv AGENTS.md; webview2/mod.rs:1936-1946) — popups are hard-denied on Windows today; macOS/Linux wry paths have no new-window handler found. [fact] keld.config.ts is read only for title/renderer/entry (keld-core hello.rs read_config_*); the arch 04 §2 `windows: { main: {width,height,titleBarStyle} }` sketch is not parsed. [fact] keld-compat has evidence schema (KEL-74) and lifecycle corpus `electron-lifecycle-v0` (3 cells, panel showcase) with oracle ids pinned to Electron 44.3.0 commit 07e4607. [fact] KEL-139 (Done 2026-09-29) explicitly excludes 'BrowserWindow parity beyond the one host window'; KEL-142 (Done 2026-10-01) ships window.keld.invoke only; KEL-143 (Backlog) owns same-native-window continuity across Bun generation loss; KEL-135 (In Progress) owns per-app persistent profile identity (future `session`/`partition` target); KEL-75 (In Progress) owns `window-bound` roles bound to an opaque host-minted `WindowGeneration`; KEL-102 (In Progress) owns guard wiring with window grants deferred; KEL-79 (Backlog) owns popup/navigation/origin policy.

- keld-wv AppWindowEvent/AppWindowCommand + keld-core app_session::coordinate_window_events — the single host UI<->session seam to grow into CloseRequested/Focus/Bounds/State events and Show/Hide/SetBounds/Destroy commands (arch 01 §4 command queue)

- KEL-64 external double-rAF first-paint beacon + the KEL-142 pre-load user-script injection seam — the only honest ready-to-show oracle; do not use PageLoadEvent::Finished/NavigationReady
- KEL-75 WindowGeneration / RolePrincipal / VirtualPortRegistry (keld-runtime registry.rs revoke_role_ports) — window close tombstones window-bound roles; BrowserWindow ids must be derived from the same host-minted generation
- keld-guard Principal::Webview{id, generation} and KEL-132 permission adapters — the per-window principal for media/devtools/popups; arch 03 §2 `windows.<name>` manifest block is the grant shape to make live (KEL-102/KEL-15), not a new schema

- @keld/api app lifecycle (whenReady/onLastWindowClosed/quit) + channels.handle + LifecycleLink demux + KEL-98 echo-codegen — generate the `window.*` channel types from one Rust source; @keld/electron stays a facade importing @keld/api, never Electron

## Platform notes

- **macOS (AppKit + WKWebView; wry/tao interim scaffold, destination objc2)**: [fact] modal = NSWindow sheet attached to parent; children keep relative position (Electron doc). [inference] titleBarStyle hidden/hiddenInset -> NSWindowStyleMaskFullSizeContentView + titlebarAppearsTransparent + titleVisibility hidden; trafficLightPosition needs standardWindowButton frame adjustment; vibrancy -> NSVisualEffectView behind a non-opaque WKWebView — research 06-webview-reality warns transparency has leaned on private API flags; must stay entitlement-clean [unknown whether achievable on macOS 12-15 without private drawsBackground]. [fact] 'unresponsive' has no WKWebView hang detector (only content-process termination). [unknown] WKWebView rAF/compositing while NSWindow is ordered out (ready-to-show oracle). [fact learnings] a key NSWindow is not proof the WKWebView is first responder; focus events must use makeFirstResponder truth. [fact] native tabs (tabbingIdentifier) and TouchBar are AppKit features available to the host; TouchBar is experimental upstream and hardware-dependent (▲). previewFile = QLPreviewPanel. setContentProtection = NSWindowSharingNone (Electron doc).

### F02-A2 — How are close/closed/destroy/'Object has been destroyed' reproduced when the host owns the window and app code runs in a separate Bun process?

**Proposed answer:** [inference, evidence-backed] Two-phase close owned by the host: (1) native close request (button, Cmd+W, app.quit sweep, parent close) -> host emits CloseRequested{window, generation, seq} and does NOT close; (2) facade emits 'close' synchronously to listeners; if no listener called preventDefault, facade replies CloseAllow(seq); host then runs page unload, destroys the webview before the window (view_drop_order invariant), decrements the lifecycle window count, and emits Closed; (3) `win.destroy()` is a separate unconditional Destroy call that skips 'close' but guarantees 'closed' (Electron contract); (4) after Closed the facade fences the handle: every method/property except isDestroyed() throws Error('Object has been destroyed'). Deadline: if the Bun generation is dead or does not answer within the admission deadline, the host honors the user's close (window closes) — Electron's observable 'user can always close' wins over a dead veto; this is an explicit ▲ to record. 'close' must precede DOM beforeunload (Electron order), so the host must not start unload before CloseAllow.

**Evidence:**
- browser-window.md 'close': 'Emitted when the window is going to be closed. It's emitted before the beforeunload and unload event of the DOM. Calling event.preventDefault() will cancel the close' (R2)
- base-window.md destroy: 'Force closing the window, the unload and beforeunload event won't be emitted ... close event will also not be emitted ... but it guarantees the closed event will be emitted' (R3)
- browser-window.md: 'Reading this property throws Object has been destroyed once the window has been destroyed'; isDestroyed note (R4)
- drawio electron.js:947-975: 'close' handler calls event.preventDefault() unconditionally, sends 'isModified' to renderer, later calls mainWindow.destroy() guarded by !isDestroyed(); 'closed' splices windowsRegistry
- Zettlr windows/index.ts:357-410: 'close' -> event.preventDefault() then async askUserToCloseWindow().then(window.close()); 'closed' deletes map entry; also app.quit() from inside 'close' on win/linux last window
- crates/keld-wv/src/view_drop_order.rs: 'Platform bindings require the webview to release before the host window closes'
