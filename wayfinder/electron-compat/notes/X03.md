# X03 — node-bun-native-addons

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

Cross-cutting runtime layer for migrated Electron main processes on Bun. Findings: (1) Electron resolves the five module specifiers (electron, electron/main, electron/renderer, electron/common, electron/utility) with one Module._resolveFilename patch to a single builtin and ships no package.json exports; Keld must do the same with ONE resolver owner — a Bun preload plugin (onResolve covers bare specifiers for both import and require) — because bunfig.toml has no [alias] key at all (architecture 04 §2 names a non-existent key; the KEL-72 fixture still writes it) and tsconfig paths is only verified for ESM import of bare `electron` on Bun 1.3.14 while CI now pins 1.4.2. (2) Process-level Electron facts (process.type/versions/defaultApp/resourcesPath/mas/windowsStore, app.getPath/getVersion/getName/isPackaged/getAppPath) are consumed synchronously at module-evaluation time by real apps (draw.io constructs electron-store at top level), so they must be host-minted and delivered at role spawn, not fetched over kipc after ready. (3) Native addon policy follows the KEL-78 four-outcome tree with no in-process load under strict: better-sqlite3 (N-API, KEL-215 qualified only for 13.0.3/Bun 1.4.2/win-x64), nodehun (N-API, node-gyp source build, imported as a raw .node file by Zettlr), node-pty (N-API 7, KEL-76 host pty row), keytar (N-API 3, archived → safeStorage over keld-native `secrets`), sharp and @parcel/watcher (N-API prebuilds → addon worker). chokidar 5 is pure JS over fs.watch — a Bun fs.watch differential (KEL-77 family extension), not addon policy; fsevents is only a transitive chokidar@3 optional in Zettlr's lock. (4) Both corpus apps spawn external executables; raw child_process stays never-listed under strict, so a scoped `process` broker (KEL-76) with KEL-77's five lifecycle oracles as conformance is on the critical path for Zettlr, while draw.io's spawns are Windows-only. (5) Profile labeling: Electron-compat apps start `unverified`, never silently `legacy`; migrate must write the explicit Keld profile key only on user acceptance and print the forfeit. (6) electron-store/electron-log/electron-context-menu are the cheapest aggregate oracle of the median main-process surface and should become an unmodified package panel in the corpus. Evidence is insufficient to state Bun 1.4.2 Node-API coverage or whether nodehun/node-pty load on it; prototypes are proposed.

## Reuse points

- @keld/api `app` (AppLifecycle: whenReady/isReady/onLastWindowClosed/quit) + LifecycleLink — @keld/electron already wraps it; every new runtime shim must stay a thin re-export, never a second kipc client (keld-cli create.rs asserts the facade must not duplicate the wire client).
- keld-guard::admit::{ProfileState, admit()} — the ONLY owner of strict/legacy/unverified; migrate/doctor/scoreboard print ProfileState::as_report_str(); never a parallel profile string in @keld/electron.
- keld-guard Principal + future Principal::AddonWorker{id,generation} (KEL-78 §4) — addon workers must reuse RoleRegistry/RoleConfig/RoleSupervisor and VirtualPortRegistry from keld-runtime rather than a new process model (briefing invariant 4).
- keld.compat.evidence/v1 + denominator/v1 (crates/keld-compat/src/evidence.rs, KEL-74) — every addon qualification row (KEL-215 shape: package version, OS/arch, Bun revision, selected/loaded SHA-256, operation, oracle, authority_profile) is a producer of this schema; no second schema.
- KEL-77 child_process_differential.rs harness and its driver.cjs + 5 Node oracles — extend with new operation families (fs.watch, N-API load/teardown) instead of a new harness; its `authority_profile: legacy_sandbox_off` labeling rule applies to all bare-runtime measurements.
- keld-native FsBroker (fs.read/fs.write scopes, $APPDATA/$DOCUMENTS tokens, KELD-NATIVE-* errors) — fs.watch and app.getPath-derived scopes extend this broker; `secrets` MODULES row hosts safeStorage; `shell` row hosts electron-store openInEditor/electron-log openExternal.
- Bun's own resolver facilities (tsconfig compilerOptions.paths; `preload` + Bun.plugin onResolve; package.json exports conditions bun/node-addons/node/require/import/default) — reuse instead of a Keld loader.
- Electron's own alias contract (lib/common/init.ts: five specifiers → one builtin) — clone the observable contract, not per-subpath packages (research 214 refuses fake named exports).
- keld-pack ExpectedAppIdentity / installed layout (KEL-19, KEL-254) — owner of what process.resourcesPath, app.getAppPath, app.isPackaged, process.windowsStore and process.mas resolve to; do not compute them in JS from __dirname heuristics.
- KEL-75 role declaration (app-bound/window-bound roles) — utilityProcess.fork env/cwd/execArgv are translated to host role policy; addon workers are roles too.
- docs/engineering/compat-scoreboard.md ▲/✘ board + keld.compat.ts quirks flags — the only two places divergence may be recorded (keld-compat AGENTS.md).

## Platform notes

- **macOS**: Strict profile = App Sandbox admission (KEL-78 T2c open); dlopen of unsigned libraries denied → nodehun/better-sqlite3 in-process impossible under strict, addon worker needed. fsevents is irrelevant for chokidar 5 (readdirp+fs.watch; Bun's fs.watch backend on macOS [unknown] — kqueue vs FSEvents affects recursive semantics). process.mas should be `true` only for a MAS-targeted keld-pack build (none exists; [unknown]). safeStorage → Keychain; keld-native `secrets` must report isEncryptionAvailable per Keychain availability. utilityProcess.allowLoadingUnsignedLibraries has no strict analog (never). WKWebView gives no Chrome version for process.versions.chrome. KEL-77 measurements exist only for macOS arm64.
- **Windows**: Strict = LPAC zero-capability token + job (KEL-78 T3 done; KEL-210): spawn of attrib.exe/powershell.exe from the role is denied → draw.io's hidden-backup and PowerShell paths need the process broker or are documented-✘ under strict. KEL-215 better-sqlite3 evidence is win-x64 only (13.0.3 pass / 12.11.1 ERR_DLOPEN_FAILED). process.windowsStore must be true only for an MSIX/AppX package — draw.io ships an appx target in electron-builder; Keld's Windows install modes (KEL-53/KEL-254) have no MSIX mode [unknown]. WebView2 is Chromium-derived (only engine where a chrome version string is meaningful). node-pty requires ConPTY (KEL-76). safeStorage → DPAPI after ready.
- **Linux**: Strict requires unprivileged user namespaces; unavailable ⇒ fail closed (KEL-78 T4), never a setuid launcher. Zettlr's tray detection spawns `gsettings` → process broker or ✘. safeStorage backends gnome_libsecret/kwallet*/basic_text must be surfaced by the secrets broker (getSelectedStorageBackend) and portal-first policy applies. WebKitGTK gives no Chrome version. - A Keld-specific native ABI or electron-rebuild-style recompilation requirement: Reuse before rewrite: Bun Node-API is the compat path (arch 04 §5, arch 06); non-N-API addons are outcome 4 (reject), not a new ABI.
