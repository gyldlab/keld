## Reuse points

- @keld/kipc transport.ts: FrameReader/WriteQueue/DrainSignal/DirectedReader, ReceivePolicy table, encodeCallError/decodeCallError, withIoDeadline — the Electron facade MUST NOT add a second reader/writer (KEL-136 AC1); el:* traffic is new ReceivePolicy rows + the existing primaryAppReceiver multiplex, not a new transport.
- @keld/api app + channels: single authenticated app-link session; ipcMain.handle/on become registrations on the same Channels owner (one handler per declared channel id, Unsubscribe pattern, listener isolation, KELD-API-001 terminal outcomes) — do not open a second socket.
- crates/keld-wv wv_link.rs private envelope + macos_bridge.rs page/isolated relay (document nonce bind, pagehide invalidation, KELD-WV-011 reasons): extend the envelope kinds (send/on/ports) rather than a second renderer-routing protocol (KEL-142 Linear: 'must not create a second renderer-routing protocol').
- keld-core app_session RendererBridgeEndpoint (RendererBridgeRequest/Outcome): the host-side pump for renderer->app CALL; future send/on/sync and host->renderer EVENT fan-out attach here, not in keld-compat JS.
- keld-runtime RoleRegistry + VirtualPortRegistry: MessageChannelMain/MessagePortMain/postMessage transfer map onto create_role_port_pair/send/transfer/close/recv/poll_role_port_disconnect; QueueFull (KELD-RUNTIME-010) and InvalidMessageLen (-011) are the existing bounds; RoleConfig::{env, env_remove, current_dir, args, restart_policy, admission_timeout} + CapturedOutput (64 KiB head / 192 KiB tail) are the only places utilityProcess.fork options may land.
- keld-guard Principal::Webview{id, generation} and DenyReason/KELD-GUARD codes; manifest 'windows.<name>.channels: ["el:*"]' shape already written in arch 03 §2 as the compat grant — implement that vocabulary in the guard, do not add a facade-side allowlist.
- keld-ipc CallError {code, message} ERR payload (one shape for every privileged channel): Electron's error.toString() reply text is a facade rendering of CallError.message, never a second ERR encoding.
- keld-compat evidence/v1 + denominator/v1 + lifecycle-corpus corpus.json cell shape (operation_id, oracle_id pinned to an Electron commit, test_path/test_name, negative_control): every F04 cell lands in that form before implementation (crates/keld-compat/AGENTS.md).
- receiver-semantics-v0.tsv one-owner golden-vector pattern (Rust and Bun replay one TSV, one digest): reuse for SCV codec vectors (TS encoder vs structuredClone oracle) and for el: envelope hostile vectors.
- KEL-98 echo-codegen.ts pattern (Rust struct -> deterministic TS types, @generated, freshness gate): the el: control-channel request/reply structs should be generated the same way rather than hand-mirrored.
- Existing KELD-* error registries: KELD-WV-011 (renderer bridge rejection), KELD-API-001 (channel contract), KELD-IPC-001..007 (transport, unchanged), KELD-RUNTIME-004..011 (virtual ports) — allocate facade-visible Electron strings as renderings over these codes, not new codes per Electron API.
- Learnings: 2026-08-15 [wv/windows] WebView2 AddScriptToExecuteOnDocumentCreated must use the async completion form (sync wait blocked UI 96-109 ms); 2026-08-14 [guard] non-AppProcess denial precedes grant lookup; 2026-08-18 [compat] a Bun fixture awaiting app.quit() with an open read loop never exits.
