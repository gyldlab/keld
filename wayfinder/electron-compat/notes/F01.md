# F01 — app-lifecycle

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

Census: 160 members (app 115 = 75 methods/30 events/10 properties; CommandLine 5; Dock 11; process 29). Keld today implements a 5-member slice live (app.whenReady/isReady/quit/on/off + ready and window-all-closed events, process.type/process.versions.electron shims) over keld_ipc LIFECYCLE_CHANNEL=3 {Ready, LastWindowClosed, Quit}; everything else in the family is TARGET, and keld-native lists deeplink/autostart/dock as names only. Corpus demand ranks: whenReady/ready, window-all-closed, quit, exit, getPath (Zettlr 40 call sites, draw.io 3), getVersion, requestSingleInstanceLock+second-instance (both apps), open-file (Zettlr 20 sites, draw.io 1), before-quit/will-quit, activate, relaunch (Zettlr), focus/show (Zettlr), isPackaged, setAppUserModelId, disableHardwareAcceleration, process.defaultApp/argv parsing (draw.io). Four design-changing facts: (1) [fact] host Ready is currently signalled on NavigationReady of a host-created window (crates/keld-core/src/app_session.rs:3900), while Electron's ready fires before any window exists — BrowserWindow compat needs Ready re-based. (2) [fact] Quit is a one-shot correlated Call with no veto; Electron before-quit/will-quit preventDefault and beforeunload cancellation (Zettlr depends on it) need a two-phase host protocol; app.exit(code) cannot be process.exit because the supervisor recovers nonzero Bun exits with a fresh generation and re-sends Ready (arch 06 §1) and treats status-zero post-ready exit as KELD-RUNTIME-012. (3) [fact] the strict Bun child receives only KELD_APP_LINK + log sinks, so single-instance lock, second-instance argv/cwd/additionalData, open-file/open-url, getPath roots and OS registrations (protocol client, login items, dock) must be host-owned and delivered as typed events/calls; research 186 row 2 already classifies the handoff tuple as untrusted input. (4) [fact] protocol-client and login-item registration are build-time declarations (Info.plist CFBundleURLTypes, .desktop, MSIX uap:Protocol) and v0 has no .app/plist/MSIX emitter (keld-auth rung 2), so the facade must return false with a diagnostic rather than a silent true. commandLine.* is on the never list (arbitrary Chromium flags) and becomes a facade-local no-op store with a one-time dev warning. Six atoms below; all labelled; unknowns kept explicit.

## Reuse points

- keld_ipc::LIFECYCLE_CHANNEL (3) and LifecycleEvent/LifecycleRequest/LifecycleResponse postcard enums — extend (QuitRequested/QuitCancelled/Exit{code}, deeplink events may be a sibling channel) rather than adding a parallel lifecycle transport; wire bytes Ready=0x00/LastWindowClosed=0x01 are pinned by tests
- keld_core::LifecycleSession (signal_ready idempotence, window_opened/window_closed → LastWindowClosed) and app_session.rs Quit ordering accept→reply→quiesce→revoke→reap→UI exit (KEL-96/KEL-139 AC6) — the only Quit owner
- @keld/api AppLifecycle singleton + LifecycleLink (framing, HELLO, deadlines, reply waiters, link-death rejection) — @keld/electron must stay a consumer (KEL-142 AC3); add BootDescriptor/SecondInstance/OpenFile handlers there, not in the facade
- keld_runtime::Supervisor + CrashLedger/SelfTerminationRecord + 'host-authorized exit after accepted Quit' rule — generalize for Exit{code}; RoleEvent/RoleRevocationCause for child-process-gone mapping
- keld_guard::PermissionsManifest `app.<group>.<action>` arrays + evaluate()/json_pointer_for + dispatch_privileged — grant shapes app.deeplink.register, app.autostart.set, app.fs.* (userData root) use the same owner; no new permission check paths
- keld_native MODULES names deeplink/autostart/dock already declared — implement under those names, no new module identifiers
- KEL-135 profile identity roots for sessionData/userData decisions; KEL-130 FsBroker retained scopes for userData writes (electron-store/electron-log)
- KEL-237 lifecycle-corpus (crates/keld-compat/fixtures/lifecycle-corpus/corpus.json) + keld_compat::evidence scorer — add cells (quit ordering, second-instance, open-file pre-ready, exit code) to this corpus; the briefing says reuse, don't fork
- keld-wv AppWindowEvent and the host window registry count — source of truth for hasVisibleWindows and window-all-closed; never a facade-local window list
- keld-auth (KEL-89) host-broker rung 2 custom-scheme analysis and keld-pack ExpectedAppIdentity — protocol/login-item materialization shares the bundle/manifest emitter (KEL-19)
- Existing scoreboard divergence pattern (▲ per host/kipc constraint vs keld.compat.ts quirks flag per app) for recording commandLine no-op, setPath('sessionData') no-op, versions.electron value
- @keld/electron index.ts process shim installation point for process.defaultApp/resourcesPath/argv re-shaping (import-time, synchronous, no kipc wait)

### F01-A1 — What does host `Ready` mean once BrowserWindow is app-created? ### F01-A2 — How do before-quit / will-quit / quit (with preventDefault and beforeunload cancellation) and app.exit(exitCode) map onto a host that owns windows and a supervisor that recovers Bun crashes?

**Proposed answer:** Make Quit two-phase and host-owned: (1) a host→app `QuitRequested{source}` Event for Cmd+Q / dock Quit / OS logoff / facade app.quit(); the facade emits before-quit, then host closes windows (running renderer beforeunload via the window module), then will-quit; any preventDefault or a beforeunload veto sends `QuitCancelled` back and the host stays alive; otherwise the facade sends the existing correlated `Quit` Call and emits `quit(exitCode)` on Reply. (2) Add a distinct `Exit{code}` Call: host replies, skips before-quit/will-quit, tears down with KEL-96 ordering and exits with `code`; the supervisor must classify the following Bun exit as host-authorized (same rule already used for status-zero after accepted Quit). `window-all-closed` must NOT be emitted during a quit-initiated close (host suppresses LastWindowClosed while a Quit is in flight). **Evidence:**
