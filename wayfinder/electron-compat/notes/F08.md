# F08 — diagnostics-crash-tracing

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

[fact] Corpus demand for this family's module surfaces is zero: neither draw.io Desktop, Zettlr nor electron-quick-start calls crashReporter.*, contentTracing.*, app.getAppMetrics, app.getGPUFeatureStatus/getGPUInfo, process.getProcessMemoryInfo/getHeapStatistics/getCPUUsage (grep over the clones, 2026-10-06). What the corpus DOES need from the diagnostics area is adjacent: draw.io listens to webContents 'render-process-gone' twice (reads only details.reason into a string) and installs process.on('uncaughtException') → app.exit(1) in export mode; Zettlr handles BrowserWindow 'unresponsive' → destroy() and logs process 'unhandledRejection'; both call app.disableHardwareAcceleration() before ready. So the sequencing answer is: (1) land the host-emitted engine process-gone and Bun-generation-gone events first (they ride on live keld-runtime CrashLedger/KEL-75 generations and on engine hooks keld-wv has not yet wired: WKWebView webViewWebContentProcessDidTerminate, WebView2 ProcessFailed, WebKitGTK web-process-terminated); (2) ship process.getHeapStatistics/getCPUUsage/getProcessMemoryInfo as a pure Bun-side facade (Bun 1.4.2 exposes process.memoryUsage, process.cpuUsage, process.resourceUsage, node:v8.getHeapStatistics, bun:jsc heapStats — probed live) with KB conversion and documented ▲ for fields Bun cannot derive (private/shared); (3) ship crashReporter as a local-state facade (start/addExtraParameter/removeExtraParameter/getParameters/get/setUploadToServer BEHAVIOR_MATCH-capable because they are pure data; getLastCrashReport/getUploadedReports honestly return null/[] because Keld has no uploader, and Electron itself only returns UPLOADED reports) with upload gated behind an explicit `net.connect` grant + opt-in — Electron's default uploadToServer:true cannot survive default-deny and is a documented ▲; (4) app.getAppMetrics must consume architecture 01 §5.1's ruled census (keld-owned processes: host, macOS guardian, Bun primary, named roles; engine helpers are separate diagnostics) and its counters (resident set + private companion, KiB) rather than inventing a second census; WebView2 GetProcessInfos gives pid+kind only (caller reads memory itself), WKWebView exposes no public web-process pid; (5) contentTracing is a documented-never in production (Chromium tracing service; WebKit has none; briefing never-list #10) delivered as an arch 07 §2 structured error; (6) GPUFeatureStatus/getGPUInfo are research: only Linux has a Keld-owned signal today (KEL-132 GpuSafeMode three-state), the enum has no 'unknown' value, so an honest mapping needs a ruling. Live Keld today: keld_runtime::CrashLedger {count, last (KELD-RUNTIME-012 + bounded stderr tail 64 KiB head / 192 KiB tail), stdout_len_at_last_crash, self_termination_count, last_self_termination}, Supervisor::crash_ledger()/current_pid(), KELD-RUNTIME-002 breaker (3 crashes/30 s sliding), KELD-CORE-033 surfacing in the no-flag host; @keld/electron exports only `app`; no crash dumps, no uploader, no process census code, no engine process-failure hooks, no GPU status API. Key new observable with no Electron analog: in Keld the developer "main" (Bun) can crash and be replaced while the host-owned window survives; the restarted generation could be told about its predecessor's death — that needs a Keld-named contract (KEL-143 territory), not an Electron API name.

## Reuse points

- keld_runtime::CrashLedger (count, last with KELD-RUNTIME-012 + bounded stderr tail, stdout_len_at_last_crash, self_termination_count, last_self_termination) and Supervisor::crash_ledger()/current_pid(): the only crash fact source; any crashReporter record, child-process-gone event, or CRASH-RECOVERY diagnostic reads it — no second ledger.
- KEL-116 SelfTerminationRecord fixed-size allocation-free shape: the hot-path pattern for any new process-gone fact (no steady-state allocation in supervisor paths).
- KEL-75 role generation lifecycle (revoke link/grants/ports before successor; ObservedAndReaped → RevokeAll → Provisioned): child-process-gone for named roles is an observation of this state machine, not a new process model.
- Architecture 01 §5.1 census + counters (keld-owned family; resident set + private companion; KiB) and the keld-benches metrics registry (MEM-IDLE, CRASH-RECOVERY): app.getAppMetrics/MemoryInfo must share this definition and any host-side per-pid reader with the harness (one owner, KEL-90/KEL-129).
- keld-guard evaluate/DenyReason with KELD-GUARD codes and the `net.connect` URL-scope matcher: the only gate for a crash submitURL; a new read capability for diagnostics must be added to the manifest schema via KEL-102, not checked ad hoc.
- Architecture 03 §2 manifest `audit.log` key as the future one owner of local crash/denial records (07 §2 notes v0 has no sink) — do not create a parallel crash log file.
- KEL-132 webkitgtk GpuSafeMode probe (three-state, non-mutating): the only honest GPUFeatureStatus input today.
- keld-wv WebView2 backend's existing event-handler registration pattern (NavigationCompletedEventHandler::create + add_*): add_ProcessFailed follows it; WKWebView navigation delegate and WebKitGTK signal plumbing live in the same per-backend modules.
- Architecture 07 §2 structured error object + crates/keld-cli/tests/error_registry.rs bidirectional registry check: for every contentTracing/unsupported throw and every new KELD-COMPAT-* code.
- KEL-74 keld.compat.evidence/v1 + lifecycle corpus fixtures (crates/keld-compat/fixtures/lifecycle-corpus): conformance cells for this family (authority_profile strict_bun; oracle = pinned Electron doc) land here, never a new scoreboard.
- @keld/electron app facade pattern (listener map, per-listener try/catch isolation, emit ordering) and @keld/api AppLifecycle/link: crashReporter and process-gone event facades extend these, not a new event bus.
- Bun built-ins (process.memoryUsage, process.cpuUsage, process.resourceUsage, node:v8.getHeapStatistics, bun:jsc heapStats/memoryUsage, process.abort) for self-process metrics and crash(): no host call, no Rust.
- KEL-143 (renderer survives Bun generation recovery) as the owner of the Keld-only 'main died, window lived' observable; KEL-78 T5 crash/hang/OOM probes as the owner of resource-limit facts.

## Platform notes

- **macOS (AppKit + WKWebView)**: [fact] webViewWebContentProcessDidTerminate(_:) fires 'for any reason' with no reason or exit code → render-process-gone reason fidelity is nil; a Keld policy (coarse 'crashed' under quirks flag) is required. [inference] No public API for the web content process pid or to disable GPU compositing; WebKit XPC helpers are not children of the app, so no engine ProcessMetric rows (consistent with §5.1 excluding them). [fact] The guardian re-exec exists only on macOS (§5.1) → an extra ProcessMetric row with no Electron type.
