# F06 — native-desktop

_Research unit of the Electron compatibility wayfinder map; generated 2026-10-06; labels [fact]/[inference]/[unknown] as written by the unit agent; two independent refuters (invariants, Electron semantics) reviewed every decision._

## Summary

[fact] F06 covers 38 entities / 350 members of the v44.4.5 model; every module is main-process only (nativeImage/shell/clipboard renderer use is deprecated or non-sandboxed only), so every call maps to Principal::AppProcess over kipc into a keld-native module that does not exist yet. [fact] Keld state: keld-native ships only the retained FsBroker (fs.read/fs.write, KEL-130, Done) and a MODULES name list (menu, tray, dialog, notify, clipboard, shortcut, screen, power, shell, secrets, deeplink, autostart, dock; 'capture' from arch 05 §3 is absent from MODULES — a code/spec gap); no F06 channel is reachable from the shipping host until KEL-102/T3 admission; @keld/electron exports only `app`. Corpus demand ranks dialog (drawio showMessageBox x7, open/save x4 each; Zettlr showMessageBox 24, dialog in 21 files) > shell (openExternal 3/7, openPath, showItemInFolder, trashItem) > Menu (both apps: buildFromTemplate + setApplicationMenu, 13 roles in drawio, 45 accelerators per Zettlr platform menu, popup with frame) > screen (workArea/getDisplayMatching) > clipboard (drawio uses the 44 W3C promise shape with ClipboardItem; Zettlr on ^43.6.0 uses sync readText and the removed writeImage) > nativeTheme (themeSource writes, 'updated') > nativeImage (createFromDataURL().toPNG(), createFromPath for icons) > Tray/Notification (Zettlr only) > systemPreferences (getAccentColor, subscribeNotification AppleInterfaceThemeChangedNotification). Zero corpus use of globalShortcut, powerMonitor, powerSaveBlocker, safeStorage, desktopCapturer, ShareMenu, pushNotifications, inAppPurchase — Tier 2/3 as arch 04 §4 already says. Six decision atoms change design or sequencing: (1) dialog-chosen paths must become host-minted, session-bound fs grants consumed by the existing FsBroker (drawio's blessPath/realpath/sibling-draft pattern is the oracle) — KEL-130 explicitly excluded dialog grants and binds scopes to an immutable manifest digest; (2) all F06 UI objects are host-main-thread handles with host-assigned ids and write-through property setters, click/event dispatch host→Bun; (3) guard grant shape for resource-less capabilities: the arch 03 `system: [...]` flat list is evaluable today as operation="system", path="<capability>" with zero guard changes; (4) shell.openExternal: the guard refuses scheme-wide grants by design while the median app's legitimate policy is 'any http(s)/mailto/tel URL the user clicked' — needs a host confirmation grant kind, not a wider glob; (5) binary payload/NativeImage model: Bun-side immutable value object + host decode at consumption, bounded by MAX_FRAME_LEN 16 MiB / 8 MiB content ceilings, with a `clipboardLegacySync` quirks flag reusing the KEL-127 blocking CALL primitive for 43-shape apps; (6) safeStorage is a host secrets broker (KEL-78 denies keychain to strict children), fail-closed where Electron Linux falls back to plaintext basic_text — blocked on the KEL-89 D5 secrets fast-follow spec. Notifications are gated by packaging identity (Windows AppUserModelID + Start Menu shortcut; macOS code signing) and so sequence behind KEL-19/KEL-103, not behind kipc work.

## Reuse points

- keld_guard::evaluate + keld_ipc::guard_dispatch::dispatch_privileged — the only authorization path; F06 adds operations/grant nodes, never a second evaluator (KEL-102 D5).
- keld_native::fs::FsBroker retained ScopePermit/grant_index selection — dialog-chosen paths, shell.openPath, shell.showItemInFolder, shell.trashItem and nativeImage.createFromPath must resolve through it (bounded no-follow traversal, device check, 8 MiB ceiling), not through a parallel path resolver.
- keld_guard `/**` scope matcher with 'grant must name a destination' rule — reuse for shell.open URL scopes; do not add a URL-glob dialect.
- keld_wv::media (MediaPermission, media_permission_decision, webview principals) — desktopCapturer/getMediaAccessStatus/askForMediaAccess plumb into this adapter and KEL-132's OS-prompt oracle instead of a new media policy.
- keld_core LifecycleSession (ready / window_opened / window_closed / quit) — ready-gating for screen, globalShortcut, Tray, powerMonitor, safeStorage must observe the same ready signal @keld/electron already consumes; `will-quit` hook for globalShortcut.unregisterAll.
- keld-wv engine LogicalSize/Rect and backingScaleFactor documentation (NSWindow points) — Display.bounds/workArea/scaleFactor DIP semantics reuse this coordinate contract; Windows screenToDipRect/dipToScreenRect are the same mapping.
- KEL-127 blocking CALL with deadline, rate limit, dev warning (sendSync replacement) — the single primitive for showOpenDialogSync/showSaveDialogSync/showMessageBoxSync and the `clipboardLegacySync` quirk; no second sync mechanism.
- KEL-98 echo-codegen + @keld/api channels (AppChannel<Request,Response>) — every F06 kipc request/response type is generated from the one contract source; no hand-written wire structs.
- keld.compat.ts quirks flags and scoreboard ▲ (arch 04 §3 item 5) — legacy clipboard shape, Linux Tray click semantics, basic_text refusal are declared divergences here.
- keld-compat evidence/v1 + denominator/v1 (KEL-74) and lifecycle corpus (KEL-237) — F06 conformance cells extend the existing corpus.json panel rather than a new ledger.
- arch 05 §3 implementation notes: objc2/objc2-app-kit (macOS), windows-rs (Windows), gtk4 + ashpd portals (Linux) — portal-first file chooser/notification/screencast is already the declared Linux path.
- drawio-desktop blessPath/assertWritablePath (realpath-canonicalised, sibling draft/backup paths, userData denial) — treat as the behavioral oracle for the dialog-grant pipeline, not as code to copy.

## Decisions (with refuter verdicts)

### F06-D1 — How do dialog-chosen paths become filesystem authority for a strict-profile Bun main without a second policy owner or a widened manifest?

**Proposed answer:** Add one host-owned 'session grant' mint: the host dialog (AppProcess principal) returns paths AND registers each as a generation-bound fs scope (open → fs.read leaf; save → fs.write leaf) into the same FsBroker retained-scope set that KEL-130 built, revoked on Bun generation death and never persisted. Sibling policy is explicit: a dialog grant covers the chosen leaf plus a declared sibling pattern (`<name>.*` in the same directory) because the drawio oracle writes `.bkp`/draft siblings; anything wider requires a manifest grant. `keld migrate` seeds static dirs (arch 03 §3) but never seeds `$HOME/**`. Electron parity point: apps see identical return shapes; the difference is that out-of-grant fs calls from the node:fs facade fail with KELD-GUARD002 instead of succeeding — recorded ✔ for the dialog cell and ▲ for the 'ambient fs after dialog' cell.

**Evidence:**
- [fact] dialog.md v44.4.5: showOpenDialog returns {canceled, filePaths, bookmarks}; app does fs itself
- [fact] corpus drawio blessPath/assertWritablePath: realpath canonicalisation + blessed set + sibling draft/backup writes; userData denial
- [fact] KEL-130 spec §1 non-goals: 'dialog grant' excluded; FsBroker::prepare consumes one VerifiedManifest and binds the digest per call (arch 05 §3)
- [fact] KEL-78 table: files outside a reviewed role-private container → deny for the strict child
- [fact] arch 03 §3: `keld migrate` seeds 'dialog → fs read of chosen paths'; arch 05 §3 dialog row: 'scoped-path grants flow into fs scopes'
- [fact] keld-auth D5/custody: 'policy snapshot is immutable per session (grant change ⇒ teardown)' — a dynamic grant must be additive-in-session, not a manifest change

**Rejected alternatives:** (a) Parent-directory grant per dialog: wider than the user's choice, violates default-deny intent. (b) Manifest-only static grants: breaks drawio/Zettlr 'open any file' flows; `$HOME/**` is a glob the guard lints loudly. (c) Legacy sandbox-off profile as the only path: makes Tier 1 dialog support a labeled downgrade for every median app. (d) Bun-side path blessing (copying drawio): policy in the child, bypasses keld-guard — rejected by invariant 2.

**Confidence:** medium — necessity is proven by spec/corpus facts; the exact mint shape (leaf+sibling vs parent dir, revocation on navigation/generation) is the open design · **Type:** grilling · **Unknowns:** Whether FsBroker's retained-root model (roots live for one verified snapshot) can accept additive scopes without re-preparation cost on the hot path; Linux portal choosers may return document-portal paths; macOS MAS securityScopedBookmarks have no Keld packaging target yet.

**Refuters:**
- none

### F06-D2 — What is the object/identity model for host-owned UI handles (Menu, MenuItem, Tray, Notification, popup) across the Bun/host process boundary?

**Proposed answer:** Every F06 object is a host-main-thread resource with a host-assigned (generation, id) pair; the facade holds a proxy whose property setters are write-through kipc calls and whose events/clicks are host→Bun messages carrying (commandId, focusedWindowId, KeyboardEvent). Menu templates are submitted as one bounded tree per setApplicationMenu/popup (host builds, assigns commandIds, executes `role` items host-side without a round trip, exactly as Electron ignores `click` when `role` is set). The default menu is built host-side when the app never sets one. Lifetime: handles die with their Bun generation (tray icons, popups, notifications, power assertions are released) — a deliberate ▲ versus Electron's GC-driven Tray lifetime. Accelerator normalization is one host-side parser shared by menu and globalShortcut.

**Evidence:**
- [fact] arch 01 §threading: host main thread = platform UI thread; keld-wv requires MainThreadMarker for AppKit objects
- [fact] menu.md v44.4.5: getApplicationMenu 'doesn't support dynamic addition or removal of menu items. Instance properties can still be dynamically modified'; default menu auto-created
- [fact] menu-item.md v44.4.5: role → 'click property will be ignored'; click(menuItem, window: BaseWindow|undefined, event: KeyboardEvent)
- [fact] Zettlr menu/index.ts mutates item.checked and serialises appMenu.items; tray/index.ts keeps `this._tray` and calls setContextMenu/setToolTip
- [fact] tutorial/tray.md: 'save a reference to the Tray object globally to avoid garbage collection'
- [fact] briefing invariant 4: no parallel process model; KEL-75 host-owned roles/ports — same pattern for UI handles

**Rejected alternatives:** (a) Bun-side menu state with host re-sync on each change (diff/patch): two sources of truth, order bugs on rapid toggles. (b) Executing `role` actions in Bun via facade: needs first-responder/webContents access the facade lacks; Electron does them natively. (c) GC-driven lifetime via FinalizationRegistry: non-deterministic in Bun; Electron's own docs treat it as a trap.

**Confidence:** high on host ownership and write-through (it is the only model consistent with the four uniques); medium on lifetime rule and click latency budget (unmeasured) · **Type:** task · **Unknowns:** Exact Electron ordering of click → menu-will-close → popup callback (needs a pinned fixture run per 214); whether Bun-side accelerator validation must mirror Electron's throw-vs-ignore behavior for invalid strings; click→Bun→UI round-trip latency vs the kipc p99 100 µs budget (menu clicks are cold, but Zettlr's popup promise race assumes <100 ms).

**Refuters:**
- none

### F06-D3 — What manifest/grant shape do resource-less capabilities (clipboard, notifications, tray, global shortcuts, power blockers) use, given `evaluate(operation, path)` is scope-based?

**Proposed answer:** Keep the arch 03 §2 literal shape `app.system: ["clipboard.read", "clipboard.write", "notifications", "tray", "global-shortcuts"]` and evaluate it with the existing matcher as operation="system", path="<capability literal>" — exact-string match already Allows, non-AppProcess principals are already denied first, and `dispatch_privileged` already skips the fs path grammar for non-fs operations, so zero guard code changes are needed; deny text names `/app/system`. Resource-bearing F06 operations stay dotted-and-scoped: `shell.open` (URL scopes), `fs.read`/`fs.write` (paths via FsBroker), `secrets` (`keychain:<app>/**`). `keld migrate` emits these literals from static Electron API detection (the usage scanner already classifies modules).

**Evidence:**
- [fact] crates/keld-guard/src/lib.rs evaluate: grant_node(operation) → array → `path_in_scope(path, scope)` exact match or `/**`; `..` denied; non-AppProcess denied before lookup
- [fact] crates/keld-ipc/src/guard_dispatch.rs filesystem_dispatch_path_is_valid returns true for non-`fs.read`/`fs.write` operations
- [fact] arch 03 §2 manifest example already uses `system: [...]` and `secrets: ["keychain:myapp/**"]`
- [fact] KEL-102 D5: keld_guard is the one evaluator; keld-core never adds a second authorization check — adding a boolean-capability evaluator would be a second rule owner
- [fact] arch 03 §3: `keld migrate` seeds the manifest from static analysis of Electron API usage

**Rejected alternatives:** (a) Dotted boolean nodes `app.clipboard.read: true`: requires a new evaluate arm and schema (second grant grammar). (b) Per-module objects with scopes for everything: clipboard has no resource, invents fake scopes. (c) Implicit allow for 'low-risk' UI (menus) via a hardcoded allowlist in keld-native: policy outside the manifest — rejected by invariant 2.

**Confidence:** medium — mechanically verified against current code; whether the guard owner accepts 'system' as a pseudo-operation (deny text/pointer ergonomics, explain tooling) is a grilling question · **Type:** grilling · **Unknowns:** Whether 'menu' and 'screen' should be grant-gated at all (fingerprinting/DoS) or implicit; whether the permission-explain tooling renders `/app/system` denials usefully.

### F06-D4 — How does shell.openExternal reconcile the guard's refusal of scheme-wide grants with the median app's legitimate policy of 'open any http(s)/mailto/tel link the user clicked'?

**Proposed answer:** Introduce one new grant kind owned by keld-guard — `shell.open` entries of the form `confirm:https`, `confirm:mailto`, `confirm:tel` — meaning: the host may open URLs of that scheme only after a host-rendered confirmation that shows the full URL (user gesture is the authority mint), while literal `https://host/**` scopes open silently. `file:`, `javascript:`, and any scheme that launches local executables are never. The host also enforces Windows' 2081-char limit and canonicalizes before matching. Electron parity: openExternal still resolves void on success; a user 'Don't open' resolves as rejection (Electron rejects on failure, so this is ✔-shaped) — denied-by-manifest is a KELD-GUARD002 rejection (▲ documented). `keld migrate` seeds `confirm:*` from detected openExternal call sites and literal hosts from string-literal arguments (drawio: drawio.com, github.com).

**Evidence:**
- [fact] crates/keld-guard/src/lib.rs + arch 03 §2: 'A grant must name a destination' — `https://**` matches nothing by design
- [fact] drawio electron.js:4348 `allowedUrls = /^(?:https?|mailto|tel|callto):/i` then shell.openExternal(url) for any host (diagram links); Zettlr attach-app-navigation-handlers.ts opens arbitrary navigation targets with `.catch`
- [fact] research 186 row 3: Electron's openExternal 'has no application allowlist or origin/prompt check'; Keld 'requires a guarded operation, caller identity, URL scheme/host policy, and user-gesture/confirmation semantics owned by the host policy'
- [fact] shell.md v44.4.5: openExternal returns Promise<void>; 'Max 2081 characters on Windows'; activate/workingDirectory/logUsage options
- [fact] briefing never-list and KEL-127: unsupported combos need explicit diagnostics + visibly labeled legacy profile, no silent downgrade

**Rejected alternatives:** (a) Allow `https://**` globs: contradicts the guard's destination rule and arch 03 §2; opens phishing/local-handler abuse. (b) Require host enumeration: breaks drawio/Zettlr link opening entirely (▲ for every click). (c) Bun-side URL allowlist (copy drawio's regex): policy in the child. (d) Legacy profile only: labels every median app as downgraded.

**Confidence:** medium — the conflict is proven; the confirm grant kind is a proposal that changes guard grammar and needs security-owner review and UX validation on three OSes · **Type:** grilling · **Unknowns:** Whether a confirmation prompt is acceptable UX for in-diagram link clicks (frequency); how `activate:false` maps on macOS (NSWorkspace options) and whether workingDirectory is honored on Windows for non-exe targets; renderer-originated vs main-originated calls — the facade only sees AppProcess, so 'user gesture' provenance must come from the host's own input tracking [inference].

**Refuters:**
- none

### F06-D5 — Where do NativeImage values and clipboard payloads live, how do they cross kipc, and which clipboard API shape is the baseline?

### F06-D6 — How does safeStorage map onto a Keld `secrets` broker, and what happens where Electron degrades to plaintext?

**Proposed answer:** safeStorage is a thin facade over a keld-native `secrets` module (keychain/DPAPI/libsecret per arch 05 §3) that the host owns; the per-app encryption key lives under the app's authenticated identity in the OS store, the host performs encrypt/decrypt, and ciphertext is returned to Bun (Electron contract preserved: app stores ciphertext itself). The strict Bun child never reaches the keychain (KEL-78 deny). Where Electron's Linux selects `basic_text` (hardcoded plaintext password), Keld reports isEncryptionAvailable=false, getSelectedStorageBackend='basic_text'-equivalent diagnostic, and encryptString throws — a declared ▲ (fail closed). Sequencing: Tier 2 and gated on the KEL-89 D5 `secrets` fast-follow spec, which also gives keld-auth durable refresh custody — one module, two consumers.

**Evidence:**
- [fact] safe-storage.md v44.4.5: Keychain/DPAPI/kwallet|libsecret; basic_text 'unprotected as they are encrypted via hardcoded plaintext password'; isEncryptionAvailable ready semantics; encryptString throws on failure; decryptStringAsync {shouldReEncrypt,result}
- [fact] KEL-78 authority table: 'Secrets / keychain / credential tokens | deny (cannot impersonate the user)'
- [fact] keld-auth.md D5: durable custody 'via a secrets module is the named fast-follow tier ... with its own spec'; arch 03 §2 `secrets: ["keychain:myapp/**"]`
- [fact] arch 05 §3 secrets row: keychain/DPAPI/libsecret → safeStorage facade
- [fact] corpus: zero safeStorage call sites in drawio/Zettlr/quick-start — Tier 2 placement (arch 04 §4) holds

**Rejected alternatives:** (a) Mimic basic_text plaintext for parity: makes the `secrets` grant a false promise. (c) keytar-style arbitrary keychain item CRUD as the primary API: Electron's safeStorage contract is encrypt-bytes, and arbitrary item access is a wider authority — keep for a later `secrets.item.*` surface.

## Never list

- Renderer-process (webview principal) direct clipboard/shell/nativeImage/screen calls: Electron deprecates renderer clipboard (v44.4.5 front matter) and shell 'will not function in a sandboxed renderer'; Keld's evaluate denies any non-AppProcess principal before grant lookup (KELD-GUARD006). - shell.openExternal / openPath targets that launch local executables (file:, app bundles, .exe/.lnk, javascript:): Research 186 row 3: unfiltered platform dispatch; no user-gesture confirmation makes this arbitrary code execution from the strict role.
- Scheme-wide `shell.open` globs (`https://**`): arch 03 §2 and keld-guard: 'A grant must name a destination'; use the confirm grant kind (D4) instead.
- safeStorage basic_text plaintext emulation: Would make the `secrets` grant protect nothing; Keld fails closed and declares ▲.
- systemPreferences.postNotification/postLocalNotification/postWorkspaceNotification and arbitrary setUserDefault/registerDefaults from strict roles: Cross-application signalling and host-process NSUserDefaults writes can alter host/WebKit behavior; legacy profile or key allowlist only.

- App-chosen Tray GUID / AppUserModelID strings: These bind OS identity; the host derives them from the authenticated app identity (KEL-135/keld-pack), never from app input.
