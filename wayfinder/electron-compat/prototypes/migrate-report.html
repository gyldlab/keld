Logic prototype for map gyldlab/keld#391, units X02 (migrate tooling), X03 (Node/Bun and native addons), X04 (security mapping). Planning only: nothing here is implemented in Keld. Today keld migrate is a reserved verb that exits 2 with KELD-CLI-045.

Bounded question. Given a static scan of an Electron app, does this state model — scan → inventory call sites per Electron member → classify against the compat matrix (✔ / ▲ documented divergence / ✘ tracked / ✘ never / unclassified) → native-module qualification lookup → security blockers listed separately → authority profile printed → five files generated only after --write → counts labelled “static estimate, not a compatibility score” → a KEL-74 claim line only against a committed denominator — ever let the report say more than the evidence supports?
How to read it: the right-hand panel is the whole analyzer state, re-rendered after every action. Buttons under “Free play” are always available; an action the real system must refuse returns a typed error instead of doing nothing. The three walkthroughs reset to a known state. “Negative controls” mutate a rendered report and show the honesty checker catching each mutation.
