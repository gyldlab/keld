## Reproduce and falsify ledger claims

Run at the pinned draft child checkout with both the prior and new source Git
objects available:

- `python -B tools/test_windows_architecture_closeout.py` — verifies rejection
  of stale/duplicate/unknown reviewer claims, forged statuses, missing public
  evidence and unowned/missing falsifiers.
- `python -B tools/windows_architecture_closeout.py --check` — rejects snapshot
  count, output-byte, triage-queue, evidence-hash and source-blob drift.
- `python -B tools/ci_inputs.py --check`, plus repository hygiene and hosted CI
  under the existing `just`/workflow contracts.

`tools/windows_architecture_closeout.py` extends, **without modifying**, the
existing reviewed queue generator `tools/windows_architecture_ledger.py`. Both
commands above run in the `audit-docs` lane: locally through `just audit-docs`
(`audit-docs-test` runs the unit tests) and in hosted CI through the hygiene
job's "Public audit registry contracts" step, whose exact command list
`tools/ci_hygiene.rs` owns. The two closeout files and the generator they
import are `audit-readers` in `tools/ci-inputs.json`; `--check` reads the pinned tree's Git objects, a live
input already declared for `audit-docs`. Evidence must cite one specific
public review comment (`#issuecomment-N`); the offline check cannot prove the
comment's content covers the blob, which stays the reviewer's attestation.
