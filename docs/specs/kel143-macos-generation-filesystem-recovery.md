## 1. Goal and non goals

Recover the admitted Bun generation in the same native window and document only after its filesystem work actually returns, its sole old `FsBroker` is destroyed, and a fresh broker has been prepared from the unchanged host policy. The existing guardian and `Supervisor` remain the only process, restart, backoff and reap owners. Core supplies the completed native retirement fact at their existing preparation boundary.

Non-goals are OS-syscall preemption, rollback, automatic replay, exactly-once effects, policy reload, new grants or principals, additional roles, Windows/Linux product qualification, new public APIs or kipc kinds, dependencies, unsafe code, signing/distribution and Rust quarantine. A truly wedged synchronous call can still stall recovery. Its renderer caller receives one terminal local rejection independently of native completion.

## 3. Acceptance criteria

1. **Policy and identity.** Across G1→G2, the host retains the original verified policy identity/digest. G2 has fresh runtime-selected endpoint/token/generation. No request, document, environment or on-disk policy edit selects authority; denied filesystem effects remain absent.
2. **Retire before provision.** On recoverable G1 loss, old link/routes/dispatch and pending-call authority become unusable, generation cancellation is set, and native admission closes. Each admitted call record terminalizes: queued work may be cancelled before handler entry; an already-entered native operation must actually return. Every per-call handle closes and the actual old broker is destroyed. Only then may fresh-broker preparation and runtime successor provisioning/authentication begin. The owner-process census of broker-owned root/call handles reaches its pre-prepare baseline between broker generations.
3. **Native stall and caller outcome.** Holding G1 inside a synchronous operation past outer expiry produces exactly one local renderer rejection, without fabricated native completion or replay. Until the operation returns, no G2 locator, spawn, HELLO/Bound, Ready, reader or privileged handler exists. The same host window/document stays alive. The fixture independently records any ambiguous committed effect.
4. **Fresh preflight and root identity.** After old destruction, the existing worker prepares one fresh broker from the retained verified policy. Each fixed anchor selects one complete object through KEL-130's existing ambient-open rule; if G1's anchor was renamed/replaced, G2 binds the replacement object, or fails if no serviceable anchor exists. It does not silently use the renamed old object or claim digest equality proves root identity. Failure preserves `FsPrepareError`/`KELD-NATIVE-008`, denies recovery, creates no G2 listener/child, leaves no prepared-root leak, and follows the existing fatal cleanup. Successful preflight alone does not admit requests.
5. **Owner responsiveness.** During native retirement, the core guardian owner continues consuming control commands, CLI lease loss and fatal observation. A failed terminal write receives its existing bounded owner acknowledgment without the worker retaining a native lease or waiting synchronously on that owner. Stale/duplicate retirement or arm completions cannot release another attempt or resurrect denied recovery.
6. **Continuity.** After fresh authentication and Ready, one successor-correlated bridge call from the same document completes an allowed exact-byte filesystem roundtrip and an independently observed denied/no-effect call. Native window identity, navigation identity and document-local nonce remain unchanged.
7. **Quit and shutdown.** Preserve T3's native terminal drain before lifecycle Quit acceptance and KEL-96's runtime attribution before its correlated reply. A core shutdown reservation closes local admission but is not the accepted-shutdown fact. Runtime denial linearizes against actual provisioning and the existing Q acknowledgment completes before core publishes acceptance; after that point no successor can provision. A provision that won before denial is rejected from current/Ready/native admission and revoked by its existing lease/Supervisor cleanup. Correlated Quit reply precedes quiesce/drain, revoke/link close, terminate/reap and UI exit. An attributed preparation cancellation may stop the Supervisor but the guardian stays live until host EOF/tail. Host death, CLI lease loss, child crash and accepted Quit remain separately attributable. Descendant cleanup and healthy next launch have their own witnesses.

## 4. Design

### Ownership and independent reasoning units

| Atom | Existing owner and boundary | Failure and first independent falsifier |
| --- | --- | --- |
| Policy | Guard verified load → host-session snapshot | Changing disk bytes changes G2 decision/digest. |
| Caller authority | Runtime authenticated generation → core trusted current context | Retired G1 token or route reaches a newly entered handler. |
| Native completion | Native borrowed broker operation → real return and closed call handles | Outer retirement is recorded as native completion while a controlled syscall remains held. |
| Broker lifetime | Existing core adapter → one actual native broker value per generation | Old prepared roots or an owning wrapper survive the retirement receipt. |
| Fresh root selection | Native one-open anchor acquisition → one complete G2 root object | A renamed/replaced anchor yields an unrecorded object, mixed identity or falsely claimed G1 continuity. |
| Restart gate | Guardian/Supervisor post-revocation boundary → fresh provision | G2 Provisioned/HELLO/Bound precedes old completion/destruction. |
| Shutdown acceptance | Core reservation → runtime denial/Q acknowledgment → accepted cause | Provision linearizes after accepted shutdown, or a pre-denial attempt reaches Ready/native dispatch. |
| Control liveness | Existing core guardian actor → bounded command acknowledgments | An owner/worker wait cycle or starvation appears under a forced failed-write schedule. |
| Product continuity | Existing host window/document → G2 correlated call | Reloaded nonce, reused correlation, duplicate effect or missing second call passes. |

Each atom has a separate oracle. Cancellation does not prove return; zero in-flight count does not prove broker destruction; HELLO does not prove Ready; surviving windows do not prove document continuity. The coupling between native completion and restart release is the explicit retirement receipt, not another owner's success.

### Sole broker value and existing worker

Keep `GuardSnapshot`'s verified policy for the host session. Its startup preflight still prepares the initial broker before listener, child or window resources. Transfer that sole value exactly once into the **existing** `FsWorker` execution state when that worker starts. The shared `FsDispatchSession` then retains verified policy, generation admission/accounting and pending-call metadata, but owns no broker/root handle. `FsInFlight` and callbacks retain only this root-free metadata. There is no `Arc<FsBroker>`, clone, second worker, new thread or borrowed view that can outlive an operation.

The existing worker holds `Option<FsBroker>` plus its bound attempt. Work borrows that value and the unchanged verified policy. On retirement, admission is closed and queued work observes the existing generation cancellation. The worker completes already-entered work, releases its native borrow and `FsInFlight`, then takes and drops its broker value. It reports old destruction to the existing guardian actor. The actor queues fresh preparation on that same worker only after accepting the exact old-attempt completion. Fresh preparation installs a new sole value with admission closed until runtime bind/current/Ready publication. Shared admission and attempt checks remain under the existing session transition; stale metadata cannot select the fresh broker.

Use the existing bounded filesystem command channel and existing guardian command channel. Extend only crate-private commands with attempt-correlated retire/prepare completions. At most one native work item, one retirement and one fresh preparation can be pending. If the single worker queue is occupied, the actor retains one pending control intent and retries nonblocking on its next poll; it never creates an unbounded secondary queue or treats a legal retire/work ordering as fatal congestion. Queue/control completion records contain no root, broker, permit or principal.

### Selected root selection rule

Each generation's fresh broker deliberately applies KEL-130 AC1 again: one ambient open at each unchanged manifest-named anchor grants the complete object returned by the OS, including a supported anchor symlink/reparse/mount. The native broker retains that object for the new generation, so subsequent namespace replacement cannot redirect that generation's operations. The digest binds policy bytes, not filesystem object identity. Automatic recovery can therefore change which root object the same literal scope names when the namespace was altered while G1 ran.

This is the concrete selection to approve, rather than an unstated continuity assumption. The child adds no broader scope strings, capabilities or caller-selected roots, but the generation-boundary object rebind itself needs permission review. Requiring the exact old root objects across broker destruction would require an additional native identity/binding contract outside this bounded cut; retaining G1 handles through a wrapper would violate the selected zero-owner boundary. Neither alternative is silently introduced.

The real-Mac oracle prepares G1 at anchor A, records its root/file identity and bytes, renames A to B, creates a distinct directory at A, and gives B/A different sentinels. G1 must remain bound to B while live. After actual G1 destruction, G2 must independently identify A's replacement as its complete newly selected root and affect only its authorized relative suffix there; an absent/unserviceable A must fail preflight before provisioning. A final rename/swap after G2 preparation must not redirect G2. Test anchor aliases separately according to KEL-130 AC1; do not claim that allowed anchor aliases are rejected traversal escapes. These observations need no new native/public identity API and cannot be replaced by digest or returned-byte equality alone.

### Preparation release and acknowledgments

At runtime `CONTROL_REVOKE(g)` close the private native-ready permit **before** exposing `Revoked(g)`. Revoke and retired-group Clear retain their current acknowledgments and ordering. The existing `CONTROL_PREPARE(g+1)` may become a pending intent, but `RoleGenerationOwner::provision` cannot run while this permit is closed. No prepared locator, child command, spawn or admission thread exists during that intent.

Split private recovery state into permanent initial-Ready eligibility, permanent denial, and an attempt-correlated native permit. Reuse the existing `arm_recovery` entry point and private core ArmRecovery command; add no exported function or type. The first arm is exclusively the initial-Ready decision, even if G1 has already revoked, and cannot release a retirement permit. Core sends it once. Later arm calls come only from the guardian actor after an exact fresh-broker completion and the preceding initial arm acknowledgment. Private core commands carry initial-versus-retirement phase and attempt; duplicates are acknowledged without another runtime arm. Runtime refuses resurrection after denial. Core validates the expected retired attempt, live session/owner and prepared-broker attempt under its existing transition before requesting release. A late initial arm, stale completion or shutdown-winning race leaves the native permit closed.

For the Clear witness, the actor may use existing `group_pid()==None` only after it knows the exact G1 Revoked attempt and expects G2's prepared-broker slot. Initial None before Spawned is not Clear. Runtime additionally requires its own recorded `cleared_attempt==g1`, successful `CONTROL_CLEARED(g1)` completion and `expected_attempt==g2` under the same private recovery guard before opening the permit. A release request arriving in the short None-before-Cleared interval remains an attempt-bound pending intent; it cannot call `owner.provision`. Denial clears that intent. No new public Clear event, query or callback is introduced.

The actor must not call a blocking native drain, join, worker acknowledgment wait or broker preparation from its update loop. Current `apply_generation_update(Bound)` runs `install_generation` on that loop, whose `fs.drain()` can monopolize it. Another edge occurs when the FS worker calls `fail_retired_generation` and waits for the same loop. Current code releases `FsInFlight` before that acknowledgment, avoiding one cycle; moving actual broker retirement there would reintroduce the cycle if the worker still awaited the owner while owning the broker. The selected change separates submission from acknowledgment: the worker releases operation/lease state, submits the existing failure command, and polls its receiver outside native processing. Its existing owner-reply absolute deadline starts at submission and is never reset by a poll. The actor acknowledges independently of native retirement and processes completion on later turns. No operation borrow, `FsInFlight`, transition/current/handler lock or synchronous acknowledgment wait crosses that edge; the idle sole broker value may remain in worker state until its retire command, and no callback owns it.

Every normal actor turn services a fixed bounded budget of commands, retirement/preflight completions and generation updates, then CLI lease/fatal observations. These polls cannot remain only in `recv_timeout`'s timeout branch, where a continuous command stream can starve them. Budget exhaustion retains bounded pending state for the next turn. No new owner, thread, public event or secondary queue is added.

### Selected shutdown and provision linearization

The runtime's private recovery state uses one serialization guard for permanent denial and `RoleGenerationOwner::provision`. Denial and the actual locator/token mint/publication are mutually ordered under that guard; a check-then-release before minting is insufficient. Reuse `GuardedPrimary::deny_recovery` with this stronger private implementation and the existing accepted-shutdown request/acknowledgment. Release the runtime guard immediately after denial; neither that guard nor a core transition/current lock may be held over Q write/read/acknowledgment. No new exported entry point or wire kind is added.

Core first reserves one shutdown cause in the existing `SessionShutdownState` under its transition. That reservation closes local work/Ready/arm admission and wins over later reservations, but `claim_guarded`'s accepted-cause publication and `begin_tail` do not run yet. Release every core transition/current lock before the actor request. The guardian actor synchronously establishes runtime denial under the shared runtime guard, then obtains the existing Q acknowledgment. Only a successful receipt permits core to reacquire its transition, commit the reserved accepted cause exactly once, start its one tail and publish the correlated Quit reply. CLI lease loss uses the same runtime ordering before its accepted-cause publication; raw host EOF still relies on the independent liveness path.

If provision wins before denial, that attempt precedes acceptance. The core reservation prevents its Bound/current/Ready/reader/native admission, and accepted Q sets the Supervisor's own stop fact before acknowledgment. Its existing post-prepare/post-spawn and lease-revoke paths revoke/close/stop/reap the attempt, and its fresh broker is disposed through the same worker. If denial wins, no listener/token can be minted. An attribution or acknowledgment failure never commits acceptance or opens the permit: report the existing typed failure and retain denial/local admission closure during cleanup. Neither success nor error is manufactured by an asynchronous core claim.

### Waiting and shutdown semantics

Preserve all existing numeric transport poll/write, partial-record, HELLO/admission, outer IPC, terminal-answer, core owner-reply, attribution and shutdown/reap deadlines. Initial preparation and ordinary Revoke/Clear/Spawned exchanges retain their current bounded transition deadlines. `await_recovery_decision`'s existing five-second unresolved initial-Ready decision budget also remains: its denial or timeout is a typed failure. Native waiting begins only after initial eligibility has been decided; removing a successor reply's total deadline must not turn unresolved initial readiness into an unbounded wait.

One explicit child-approved change is necessary: a successor Prepare's **zero-byte wait for native release** has no total five-second control-transition deadline. Today `control_exchange` applies that deadline to every exchange, which would falsely terminate a legal KEL-130 native stall. Only this waiting phase is excluded. Once a response starts, bounded record/framing checks apply; malformed, split, mismatched and unexpected records remain typed failures. A silent live host bug can therefore stall recovery in this phase, as can a real wedged operation; it cannot grant authority. This limitation is explicit, not a claim that the existing overall Prepare deadline is unchanged.

The host generation worker stores the pending Prepare and polls the permit/control health instead of blocking the core actor. The guardian's existing liveness loop still observes Q/S/EOF independently. Its private preparation-cancellation state interrupts the pending read only after Q sets the Supervisor's accepted-shutdown fact, or host EOF sets its shutdown fact; it carries neither policy nor restart authority. S retains its existing attribution role and does not alone invent a completed stop. Native-pending denial prevents provision while the channel remains available for attribution, rather than manufacturing a Prepared response or killing the attribution channel prematurely. Preserve the Q acknowledgment before requested shutdown completion. At the generic Supervisor's existing prepare-error branch, intentional interruption is `Stopped` only when its own shutdown/accepted-shutdown fact is already set; all unrelated preparation failures remain fatal. A race after actual provision uses the existing prepared-lease revoke path. Raw host EOF never waits for an impossible host RPC.

For an attributed pending-Prepare cancellation, `SupervisorEvent::Stopped` stops only that supervisor. The existing guardian liveness loop records the terminal outcome and continues waiting for the host's liveness EOF; it does not return and exit the guardian merely because Stopped arrived. This keeps the persistent guardian healthy while core waits for real native return and its final tail. Real Failed/CrashLoop/fatal control events remain failures, and an unrequested Stopped remains terminal failure. Host `poll_fatal` continues to reject unexpected guardian exit, including exit zero; no blanket accepted-shutdown exemption hides a premature guardian death. On the host tail's actual EOF, the guardian completes its attributed outcome, exits, and the existing `GuardedPrimary::shutdown` waits/reaps it normally.

Intentional cancellation may interrupt the successor's zero-byte Prepare wait. Once any Prepared response byte has been consumed, finish/validate that already-started response within its existing bounded record budget and construct the normal prepared lease; the Supervisor's own stop check then consumes that lease through its existing revoke path instead of spawning. Malformed/partial/timeout failure remains typed and keeps the existing preparation-failure cleanup.

Stopping the preparer also drops its generation-control stream. For a provision-before-denial winner that the guardian never claimed, the host generation owner may still hold `RoleGenerationLease`/`current_attempt` even though no registered group exists. The host owner must take that **exact** unclaimed/unspawned attempt's lease, explicitly call its existing `GenerationLease::revoke(Shutdown)`, emit its normal Revoked fact and clear the unregistered attempt state. This is the same existing owner cleaning its value; it does not rely on the Supervisor's post-prepare path, an implicit Drop, a new hook or another restart owner. Native preflight state for that rejected attempt retires through the same worker.

Only after that cleanup succeeds, the exact attempt has no lease/current group/listener, no partial incoming record remains, and Q attribution is acknowledged may host EOF be a clean cancelled-control completion. If EOF arrives just before the host finishes reading Q acknowledgment, retain the EOF fact and classify it within the existing five-second attribution budget; never report success from denial alone or wait unboundedly for attribution. Revoke/cleanup failures, active/spawned-generation EOF, malformed/partial records and unattributed EOF remain typed failures. This expected control closure does not imply the persistent guardian exited and does not weaken `poll_fatal`.

### Runtime seam and unchanged contracts

Before: one host-session broker survives Bun rotation; successor is already authenticated when core waits for old work. After: the verified policy survives, the old broker actually retires, the same worker reselects anchors/preflights the next broker, and the existing runtime owner then provisions/authenticates. Shutdown acceptance follows runtime denial/Q acknowledgment, and the persistent guardian survives an attributed supervisor stop until the host tail. Window, process, guardian, generation counter, trust, guard and native effect ownership classes are unchanged. Broker lifetime/root reselection, acceptance linearization and existing private preparation waiting semantics change and require the child gate.

Capabilities and manifest/schema changes: none. Public Rust/TypeScript identifier changes: none. Public kipc bytes/kinds/errors: none. KGC1 remains the same 404-byte private record with kinds 1–8; ordering/waiting semantics change and require private wire review. No new callback hook, native API, dependency, unsafe or OS primitive is selected. No performance improvement is claimed. Compatibility fallback is not required: an early-provision fallback violates the approved parent.

## 7. Test plan and first falsifiers

The first failure-first run uses the real macOS guardian with a nonempty retained filesystem scope and existing controlled-operation fixture. Hold G1 native work past outer expiry, kill admitted G1 Bun, and observe one renderer rejection. Existing runtime Provisioned/Spawned/LinkBound/Bound witnesses must remain absent until native return, actual broker destruction and fresh preflight. The current implementation is expected to fail the provision/authentication ordering; paired streams or an empty `{}` manifest cannot prove it.

Use the existing isolated native owner-process handle census to establish pre-prepare baseline, G1 prepared-root census, held-call census, baseline after actual old destruction, and G2 prepared-root census. Attribute the census to broker-owned root/call objects; unrelated window, guardian and IPC descriptors can remain live. The core actor's natural completion cut before it queues fresh preflight provides the census point; test the production state transition directly without adding a production observer/hook. Retain one wrapper or root as a negative control: the old-destruction row must fail. Logs and in-flight counters are not the independent census.

Force failed terminal write, old retirement, pending Prepare and failure-ack delivery in both orders. Withhold the ack while the actor continues polling and then acknowledge within its existing budget; the worker can destroy its broker and the actor remains responsive. A mutation that blocks the actor in drain, holds a native lease/value over the ack, or waits for native completion before acknowledging must fail this schedule. Hold native work beyond five seconds to distinguish the approved native wait from control/HELLO/owner deadlines; independently corrupt or partially send a record to ensure real transport deadlines still fail.

Race late initial arm, duplicate/stale FsRetired/FsPrepared, failed fresh preparation, accepted Quit, CLI lease loss, host EOF and guardian death against every preparation phase. Mutations removing attempt/denial checks or releasing the gate before old drop must fail. Shutdown interruption must produce its own attributable outcome and cannot mint or leak a locator. Keep existing real stale-token and next-launch positives.

Independently fence initial None versus a retired-group Clear, None before `CONTROL_CLEARED` acknowledgment, unresolved initial readiness past five seconds, and a continuous bounded command stream while FS completions/CLI/fatal observations wait. Initial None must not release G2; early release stays pending; unresolved readiness retains its typed timeout; repeated worker polling cannot renew an acknowledgment deadline. Delete only a normal-turn poll or change a deadline to restart per poll as negative controls.

For the shutdown race, fence both sides of the runtime denial/provision guard: release the native permit, reserve core shutdown before its Q request, and permit either runtime winner. A provision winner must precede accepted-cause/Q-reply publication and must never reach current/Ready/native dispatch; a denial winner has no Provisioned witness/locator. Separately fence host provision before any guardian Prepared byte, a partial valid Prepared response, full response before prepared-lease construction, and post-lease/pre-spawn. Each cut must either finish the normal lease-revoke path or positively observe exact unclaimed host-owner revocation before resource-free EOF completion; preserving the wrong attempt or swallowing a cleanup error must fail. A mutation restoring a separate atomic permission check plus later mint must fail this schedule. A second fixture accepts Q/CLI shutdown while native retirement is held, observes Supervisor Stopped and expected control EOF, and repeatedly performs the existing guardian-health observation before releasing native work. The guardian must remain the same live process until host EOF/tail. Deliver Q acknowledgment and EOF in both orders; unattributed/partial EOF must still fail. Restoring the unconditional Stopped break must produce unexpected GuardianExited or fail the liveness witness. A real unexpected exit-zero negative remains fatal.

For continuity, independently inspect native window identity, unchanged navigation/document nonce, exact successor correlation, allowed bytes, denied outside sentinel, one pending-call outcome and duplicate/ambiguous effect sentinels. Finish with real descendant instance/handle witnesses, guardian/host exit and a healthy next launch. No timer sleep establishes ordering; deadlines are kill switches. Risky cases run in bounded hostile subprocesses. Windows/Linux remain unclaimed.
