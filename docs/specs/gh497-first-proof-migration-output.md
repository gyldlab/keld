## 1. Goal & non-goals

Define one auditable, reversible, fail-closed output contract for the first macOS draw.io migration. Default `keld migrate` only inspects source and prints a **static estimate, not a compatibility score**. `keld migrate --write` may modify only the approved, owned output set after explicit write approval, and may request Legacy only after **separate affirmative acceptance of its reduced security guarantees**. The specification is the common contract consumed by GH-499's hand-authored fixture, not a hidden second resolver, profile source or permissions evaluator.

Non-goals: implementing the CLI or analyzer scanner (X02-T7/X02-T8); building, installing or executing draw.io (#589); schema inventions for #452/#453; changing #586/#588 profile admission, #541/#552 channel evaluation or #502 package resolution; automatic source patching or dependency installation; asserting strict sandbox security under Legacy; publishing a KEL-74 product score, install PASS, percentage or native evidence from static source inspection.

## 4. Design

**Atomic owners and trust.** The analyzer is untrusted static input: neither application source nor a renderer can mint Host authority. The CLI is the proposed report/write coordinator only. Root Keld config, permissions guard, package resolver, Host role-spawn, profile admission and product evidence remain their listed owners. Scanning source is not an OS receipt. Filesystem changes require explicit `--write`, an immutable preimage manifest, conflict detection before edits, bounded atomic writes, a complete per-file diff and a reversible rollback plan; a partial write must be reported as failure, never success.

**Normative output mapping (planned, not automatically valid on current main).** Each row names one existing or future parser/admission owner and the earliest relevant consumer/negative-test identifier. A missing implementation means **BLOCKED**, not permission to make up a key.

|---|---|---|---|

The following are **qualification prerequisites, not additional migrate-written keys or a new receipt schema**:

| Prerequisite | Owner and consuming boundary | Consumer test/gate |
|---|---|---|
| Actual installed package/lock/files and effective configuration | #499 artifact producer, using the approved SDK producer and upstream resolution; existing launch path consumes its admission | M15/M16 + GH-499 A01/A10 and GH-502 R07 |
| Refusal before evaluation and disabled runtime auto-install | #593 under KEL-75 / existing Host role-spawn owner; consumes the graph admission without duplicating its producer | M15/M18 + GH-499 A15; ordinary, declared-env and restart cases |
| Actual entry-relative layout and canonical transport delivery | Existing `keld-cli::boot` dev-stage/package owners; #499 supplies the complete application artifact | M17 + GH-499 A01/A09/A13 and the canonical SDK transport/Source qualification |

**Forbidden or removed outputs, each printed verbatim with a reason:** `keld.build.ts` — `not generated: keld build is reserved (KELD-CLI-045)`; `keld.compat.ts` — `not generated: no schema or live reader`; Bun `bunfig.toml` electron alias — `not generated: package dependency is the sole #502 resolver`; tsconfig/jsconfig Electron mappings — `not generated: second resolver forbidden`. The existing root `tsconfig.json` `compilerOptions.paths.electron` removal retains `removed if present: second resolver forbidden`, with its previous value and explicitly approved reversible diff. This does not expand the writable set to inherited, shared, third-party or other unowned mappings: diagnose their effective conflict with its source/owner and refuse qualification until that owner resolves it. No generated overriding config may hide the conflict. No `fs` grant from a dialog selection; no update-feed network grant from `autoUpdater`. `disableBlinkFeatures`, Chromium switches and `setFeedURL` values appear under dropped inputs with their owner-specific reason.

**Filesystem output boundary.** The first-proof migrator does not generate or edit `app.fs.read`/`app.fs.write` scopes. Legacy remains authenticated and guarded; selecting it does not disable scoped Guard filesystem enforcement. Pre-existing, separately approved scopes retain their exact semantics: migration neither removes nor widens them. New filesystem grants or edits are out of scope and deferred to separate manual work by the application/fixture manifest owner, under architecture 03 and the existing `keld-guard` manifest/`evaluate` owner, consumed by `keld-native::fs::FsBroker` (KEL-130) through `keld_ipc::guard_dispatch::dispatch_privileged`. Thus open/save remains blocked when a required read/write scope is absent or a chosen path is outside its approved scope. Report that separately owned work; neither a dialog nor Legacy authorizes inferred current/future picker paths, wildcard scopes or additional migrate-written keys.

**Installed graph and pre-evaluation ownership.** Standard package installation supplies the `electron` alias. GH-502 maps `electron`, `electron/main`, `electron/renderer`, `electron/common` and `electron/utility` to one synchronous physical entry; it owns exports/singleton behavior, not admission of an app that may never load that entry. GH-499's first-proof artifact binds the actual approved producer, lock and installed files, the real app/dependency importer locations and the runtime resolution conditions. A root manifest name, one root resolution or package-local duplicate guard cannot establish this evidence. Missing/foreign/root-substituted/dependency-local targets must be refused without importing a candidate to identify it; inspect real npm Electron only as data. Controlled execution-sensitivity negatives use an authored sentinel, not genuine Electron evaluation.

The existing CLI staging/package and Host spawn path consumes that admission **before evaluating application or dependency code**. It must preserve the admitted resolution inputs into the actual launch and each new generation; changed files, configuration, import ancestry or spawn conditions invalidate prior admission. The launch owner must refuse until the graph's owner supplies valid evidence for those inputs. This is a required contract edge, not a new loader, validator algorithm, config field or admission authority. GH-593 separately supplies no-runtime-auto-install through its approved KEL-75 spawn contract. Its older planning note that an installed root alias makes the guard unnecessary for the first proof cannot waive GH-502 R07 or M15/M18. The native no-install flag alone neither validates an already installed target nor supplies the required Keld diagnostic.

M01 remains unchanged: default migration analysis executes no app/config code, child resolver or installation. Installed-artifact verification belongs to the separately owned qualification step. A successful reversible declaration edit with a stale lock/install reports that limited result and the blocked qualification; it never reports a launchable graph.

**Effective configuration.** Qualification covers the actual lookup from every relevant importer for all five reserved names. Relevant tsconfig and jsconfig discovery, inherited `extends`, exact and wildcard mappings (including `electron/*` and any broader pattern that redirects a reserved name) are inputs even when no literal root `paths.electron` remains. Upstream resolution and approved artifact conditions remain the mechanism; do not add another resolver or execute config to emulate it. Report/refuse an effective mapping that bypasses the admitted package/exports. Other application mappings do not become migration-owned or forbidden merely because a tsconfig/jsconfig exists.

**Actual delivery and canonical transport.** Current `stage_dev_boot` places a nonce stage under the project at `.keld/dev/<nonce>` and stages the configured entry, optional renderer and optional `src/kipc-transport.ts`. The nested location can still resolve packages upward; absence of a copied `node_modules` directory is not proof of failed resolution. Conversely, copying only the entry does not deliver its relative siblings or assets. The pinned draw.io `src/main/electron.js` imports siblings such as `args.js` and `window-bounds.js` and derives `electron-preload.js` and webapp paths from its own location. The existing CLI boot/package owner and #499 consumer must qualify that actual layout and admitted upward graph, preserving entry/resource semantics rather than adding arbitrary absolute-import rewrites or a second launcher.

The existing canonical SDK/KIPC transport owner also remains unchanged. Its legitimate preload must capture before app code, and the actual installed SDK import must use the qualified canonical transport instance. Equal source bytes, a filename or a stamp do not establish module-instance identity or transfer Source retention/capture evidence. Do not inline, copy or replace KIPC to hide missing delivery. These are implementation/product prerequisites; neither the authored mechanism probes nor approval of this document passes them.

**Report contracts (future, not live).** A human report starts `Keld migrate static analysis — <project>`, then an explicit `static estimate, not a compatibility score` label, four count rows `✔`, `▲`, `✘`, `unclassified`, granted and denied proposals, security profile/forfeiture, omitted files/reasons, dropped inputs and planned diff/rollback receipt. On read-only analysis, `planned` must not say `written`. A JSON result wraps the same estimate and *actual* `DoctorFinding {label,ok,detail,error?}` values; every error uses the existing `KeldErrorObject {code,message,cause?,fix,docs}` shape. Do not invent a stable CLI error code without its error-registry owner or turn a hypothetical output into a live result. Only an independently committed KEL-74 corpus can add its separate qualified product-claim line.

**Existing abstractions and alternatives.** Reuse the current exported-root config scanner and guard manifest parser; do not execute arbitrary `keld.config.ts`. A second `electron` resolver through a Bun alias, TS paths, plugin or duplicated CommonJS entry conflicts with #502; use package-manager dependency resolution. Rejected: app-env authority, wildcard/`el:*` grants, automatic FS scope from a dialog, unsupported percentage claims and `keld build` output while the verb is reserved. No new Rust wire, FFI, principal, dependency or privileged channel in this spec.

**Platform/lifecycle.** The report grammar is platform-neutral; the initial draw.io artifact is macOS-only under explicit Legacy, and it forfeits Keld's strict zero-ambient-authority claim. #446's facade selection requires `initialWindow: "none"` and no `renderer` key. At inspected main `460815b32557f06450fba4a05517389ac8cdead3`, the CLI emits schema 2 and Core maps `ValidatedInitialWindow::None` to `HostInitialized` on the macOS facade path. The current Electron package also exports a `BrowserWindow` subset. Those are source facts, not a native acceptance rerun or proof that the original draw.io graph is delivered. The ordinary non-facade example in architecture 04 remains schema 1. Linux/Windows facade acceptance is unknown. The proposed CLI owns atomic file writes and rollback artifacts only; Host still owns spawned role facts, root permission verification, authenticated window/document generations and application lifecycle. Package identity, JavaScript globals and a static report mint no authority. No process, handle, crash or principal ownership changes; no performance rewrite is selected.
