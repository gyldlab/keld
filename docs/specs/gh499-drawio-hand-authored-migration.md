## 1. Goal & non-goals

Produce an auditable, **hand-authored** description of exactly what KELD's future `keld migrate --write` must output for **draw.io Desktop 31.7.0** on macOS with **affirmatively requested Legacy**, and later provide a real reviewable migration output under the approved #497 key-to-owner contract. The proposed macOS-only source contract enumerates two separately gated adaptations: dirty-close handling and the first disposable Legacy editor document's resource-entry/navigation/sender handling. The dirty-close proposal replaces the synchronous dialog with an awaited asynchronous one, unless native macOS proof later permits the unchanged-dialog synchronous route. The custom-entry adaptation follows the already chosen Legacy-only direction; its exact source bytes and native interfaces remain unapproved. Every output must be identifiable, reversible and independently validated. This spec authorizes **no runtime implementation** before its exact-content human approval.

Non-goals: no generalized `keld migrate` generator, full app compatibility, automatic source rewriting, installer, code signing or notarization, strict OS containment under Legacy, self-generated `el:*` permissions, implicit profile downgrade, extra bundler/compat configuration, second module resolver, new JS/TS formatter, KEL-74 product percentage, or app log taken as a Host-origin receipt. Actual application launch/Open/Edit/Save/dirty close belongs to #589, not the static artifact.

### 4.3 Channel census: source, trace, and authority are different

At the immutable main file SHA in §2, there are **26 active literal `ipcMain.on/once/handle` call sites and 24 distinct active channel names** (three uses of `app-load-finished`). **A naive regex incorrectly reports 27/25** because `src/main/electron.js:1098–1101` contains a fully **commented-out** `/*ipcMain.on('log', ...)*/` call; it cannot create a channel grant. PANEL-P3's decision [at `23f50274`](https://github.com/gyldlab/keld/blob/23f50274/wayfinder/electron-compat/probes/panel-p3/p3_decision.md#c-fix-it-list-keld-migrate-output) proposed 15 candidate grants: `rendererReq`, `app-load-finished`, `isModified-result`, `saveAndClose-result`, `draftRemoved`, `newfile`, `toggleSpellCheck`, `toggleStoreBkp`, `toggleGoogleFonts`, `toggleFullscreen`, `zoomIn`, `zoomOut`, `resetZoom`, `export`, `export-finalize`. An independent **comment-aware** source review verified **all 15 are active main-side literals**. Its tight first-proof demand was **three candidates**: `rendererReq`, `app-load-finished`, `isModified-result`. **PANEL-P3 used a script in place of a real renderer, queued dialogs, and assumed Ready ordering; it did not produce a Host-authenticated real window or document-generation receipt.** These 15 names are therefore source+synthetic-trace candidates, **not** 15 automatic permissions, proof of current channel enforcement, or completion of #541.

Four explicit exclusions: `__ELECTRON_LOG__` and `electron-store-get-data` come from libraries without sufficient sender validation; `openDevTools` is debug-only; `checkForUpdates` is out of the update-disabled four-step path. The two library channels are *not* among the **24 active main-file literals** and must never be seeded merely because the dependency can register them. Other active main-file literal registrations, such as `svg-data`, `render-finished`, `xml-data` and `import-success`, require their own observed workflow trace and owning grant decision; do not union the whole **24-name** set.

Procedure: inspect the exact source and imported modules using a **syntax- and comment-aware** registration census (do not promote text in `//`, `/* */`, template strings or unused examples into active handlers); enumerate only actual literal registrations with file/line and handler phase, intersect them with the **synthetic PANEL-P3 operation-demand trace** as a preflight filter, then require **new, independent real-macOS #589 Host-owned window and navigation/document-generation observations** before admitting a particular per-window `channels` map under #541. The research trace has no trustworthy window principal. Static source/demand agreement is necessary but **not sufficient**. Mark any computed/dynamic registration **unenumerable** and require a human-reviewed explicit literal before granting it. Never allow `el:*`, prefix/wildcard matching, missing or wrong-generation window scopes, renderer/preload requests that create authority, or library channels by default. Native tests must prove forbidden channels fail prior to entering Bun.

### 4.4 Enumerated, separately gated source adaptations and acceptance limits

The pinned original `src/main/electron.js:851` handler is already `async`. On macOS it presents `Save`, `Cancel`, `Discard Changes` in indices **0, 1, 2**, sets `modifiedModalOpen`, correlates `uniqueIsModifiedId`, registers `saveAndClose-result` on the save path and destroys only after a successful result. The **separately gated dirty-close proposal** replaces the call start and terminal assignment:

```diff
- let response = dialog.showMessageBoxSync(
+ let response = (await dialog.showMessageBox(
    mainWindow,
    { /* retain the exact pinned original dialog options unchanged */ }
- });
+ })).response;
```

The actual pinned call spans lines **876–887**; the above is a *description of one two-line hunk*, not an independently applied/verified patch or permission to change the object. Record the **exact** generated patch and its preimage, bytes/hunks, applied file SHA, and a revert control. **The changed shared JavaScript handler would run unconditionally on all platforms if distributed:** the phrase *macOS-only* restricts this **entire patched artifact's admissible platform to macOS**; it is **not** a source-level `if (isMac)` guard. The upstream line 875 warns about an async/destroy crash on Linux, so applying this artifact to Windows/Linux or claiming cross-platform correctness must fail until a separately reviewed, platform-gated patch and native acceptance exist. The async replacement changes event-loop interleavings; its correctness remains **UNKNOWN** until native Save/Cancel/Discard/repeated close/two windows/quit and delayed-result observers qualify. If either adaptation or its approved bridge fails, do **not** add undeclared hunks: report the failure and seek a revised reviewed contract. Omitting the dirty-close patch requires the real #564 synchronous dialog transport to pass; the custom-entry adaptation still makes the full main source-modified. A config-only or wholly unmodified-source claim cannot rest on a test stub.

The repository owner has recorded the user's chosen product direction for one honest local **Legacy-only custom-resource origin** in [GH473 comment 6398386345](https://github.com/gyldlab/keld/issues/473#issuecomment-6398386345). This draft translates that choice into a proposed GH499 source contract; it does not reopen the product choice or approve runtime implementation. The narrowly permitted semantic changes are: retain physical `codeDir`/`codeUrl`; obtain and load the separately Host-admitted resource entry while preserving original query semantics; and replace the original file-prefix sender predicate **for that entry** with exact admitted scheme/authority/entry matching plus canonical GH542/GH467 native WebView/frame/current-document/source eligibility. The final GH552 exact-channel Guard under current role/window policy remains independent. No URL text (including custom `URL.origin == "null"`), renderer token or Bun argument mints authority. No fake `senderFrame.url`, GH499-owned document mint or nonce/generation, global origin registry, JS entry API, IPC envelope or policy parser is permitted. Exact entry issuance (GH471/GH473), native metadata interface (GH542/GH467), authenticated source-byte admission (GH499/source-admission owner) and complete patch bytes remain open; this specification selects no placeholder API. The existing dirty-close proposal remains a separate decision. Original renderer, webapp assets and preload bytes are unchanged; the full adapted desktop main is honestly **source-modified**.

Initial custom-entry scope is **one disposable editor document** under existing KEL-135 dev-store ownership. Cross-launch browser-storage continuity, exporter/importer windows and persistent origin migration are outside this amendment. Actual file save/reopen still needs independent proof; a new disposable document after relaunch does not prove persisted browser storage. No broad `protocol.handle`, universal filesystem/network grant, page-native handler, convenience Host API or whole Wry replacement is authorized.

Retain a separate **unadapted Electron/file reference**: the original main sender predicate accepts the genuine reference file URL and rejects the custom URL. Record that rejection as an **original-identity divergence**; an adapted-path success proves only the explicit Legacy adaptation, not Electron file parity. P3's symlink/URL mismatch remains a failed original-file observation, never permission to forge file metadata.

Whole-app blockers independent of these adaptations: the two `session.defaultSession.webRequest` registrations at source lines 994/1010 must complete before later `ipcMain` setup, and every window must produce **zero** `will-attach-webview` events. Native committed/sender URLs must truthfully identify the admitted document. Do not substitute a mock or source-only promise for these native facts.
